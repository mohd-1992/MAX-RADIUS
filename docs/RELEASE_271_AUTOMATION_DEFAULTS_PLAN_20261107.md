# إضافة مهام افتراضية مفعلة إلى2.7.1 — 7 نوفمبر2026

**الحالة: متطلبات موثقة بطلب المستخدم، غير منفذة وغير مجدولة فعليًا.** تضاف إلى الإصلاحات والاختبارات السابقة، ولا تلغيها. الإصدار غير معتمد للإرسال. لا بناء أو رفع أو تحديث أو تعديل مهام عميل/دومين في هذه الخطوة.

## المتطلبات التي حددها المستخدم

تظهر تلقائيًا **ست مهام مفعلة** في صفحة الأتمتة عند تثبيت/ترقية الإصدار ضمن النطاق المعتمد، لأن التقارير الأسبوعية والشهرية تعريفان مستقلان:

| المهمة | المتطلب المحدد |
|---|---|
| حذف الكروت المنتهية | كل3أيام عند06:00صباحًا؛ سبب الانتهاء الأسبق من الوقت أو رصيد البيانات؛ مضى على الانتهاء14يومًا؛ حد الجولة5000كرت؛ المحرك المشترك المعتمد وحفظ المال والاستهلاك. |
| تلخيص الجلسات القديمة | يوميًا04:00فجرًا؛ محرك التلخيص المعتمد مع حفظ الكروت والحصص والمال والأختام. |
| تنظيف الملفات المؤقتة | مرة أسبوعيًا، ضمن النطاق الآمن المعتمد. |
| تنظيف السجلات التشغيلية | مرة أسبوعيًا، مع حفظ المال والمحاسبة وأدلة التسوية ومعرفات منع الإعادة. |
| تقرير مبيعات أسبوعي | مرة أسبوعيًا عند منتصف الليل، بعد اكتمال فترة الأسبوع. |
| تقرير مبيعات شهري | مرة شهريًا؛ بالتنسيق المشترك واسم الشهر والسنة. |

الأوقات بتوقيت النظام المحلي؛ المرجع الحاليAsia/Aden(+03:00)، مع بقاء تخزين واستحقاق الأتمتة بـUTC. لا يعتمد الجدول على توقيت الحاوية الافتراضي.

## توزيع مواعيد مقترح لاستكمال ما لم يحدده المستخدم

المواعيد التالية **اقتراح تنظيمي مسجل وليست أوقاتًا إضافية أملاها المستخدم**. المستخدم حدد06:00للحذف و04:00للتلخيص ومنتصف الليل للأسبوعي، ولم يحدد يوم التنظيف أو توقيته أو توقيت الشهري:

| المهمة | الموعد المقترح |
|---|---|
| التقرير الأسبوعي | الاثنين00:00، بعد نهاية الأحد؛ يطابق نافذة الأسبوع المكتمل الاثنين–الأحد الموجودة بالكود. |
| التقرير الشهري | اليوم الأول من الشهر00:30، لتقرير الشهر السابق المكتمل. |
| تنظيف المؤقتات | الاثنين01:00. |
| تنظيف السجلات التشغيلية | الاثنين02:00. |
| التلخيص | يوميًا04:00، كما طلب المستخدم. |
| حذف المنتهية | كل3أيام06:00، كما طلب المستخدم، بمرساة بدء ثابتة. ليست أيام الشهر3و6و9... التي تختل عند نهايته. |

عمر الجلسات للتلخيص ومدد الاحتفاظ للمؤقتات والسجلات لم يحددها المستخدم في الإضافة. القيم الحالية90يومًا للجلسات و7أيام للمؤقتات و90يومًا للسجلات مراجع افتراضية قائمة، **وليست تغييرًا جديدًا معتمدًا للمدد**. يلزم تثبيت القيم النهائية في تعريفات الإصدار واختبارها؛ لا تخلط مع عمر انتهاء الكروت14يومًا المحدد صراحة.

## منع تزامن المهام

- توزيع الساعات وحده لا يكفي؛ يجب ألا يبدأ عاملان لهذه المهام معًا إذا طالت مهمة عن نافذتها. يحفظ المنع في جهة الخادم وبالأقفال المشتركة، وليس مؤقت المتصفح.
- عند انشغال العامل، ينتظر التنفيذ الذي لم يبدأ دوره وفق سجل واضح، دون تشغيل متوازٍ أو تكرار موعد. لا يعاد تلقائيًا تنفيذ عملية بدأت ثم أصبحت نتيجتها غير مؤكدة.
- التأجيل المقصود بسبب انتظار الدور لا يتحول إلى تخطٍّ خفي لمجرد تجاوز90ثانية؛ يختبر مع سياسة المواعيد الفائتة والتعافي الحالية. فترة التقرير مرتبطة بموعده المقصود حتى لو تأخر التنفيذ.
- تنسق أقفال الصيانة مع النسخ والاستعادة وإعادة المصنع والعمليات الثقيلة الأخرى. تظل حماية الموارد والترخيص سارية؛ لا يعالج التعارض بتعطيل الحماية.

## إنشاء المهام الافتراضية والتحديثات المتكررة

- الإنشاء تلقائي والتعريفات مفعلة كما طلب المستخدم، مرة واحدة بمفتاح ثابت لكل تعريف، لا بالاسم وحده. لا تكرار عند إعادة تشغيلWebأوإعادة تهيئة الجداول أو تكرار الترقية أو تزامن عاملين.
- لا تُمحى تعديلات المستخدم على المهام أو تعاد المهام التي حذفها أو عطلها بمجرد تحديث الصفحة/الخدمة. يلزم حفظ حالة اعتماد الافتراضيات بطريقة تميز أول تثبيت من التعديلات اللاحقة.
- لا تشغيل تعويضي فوري للحذف عند الترقية بسبب موعد سابق؛ يؤخذ أول موعد مستقبلي صحيح ضمن مرساة الجدولة.
- القواعد القديمة المشابهة تُجرد قبل الترحيل وتسوّى دون تشغيل نسختين من المهمة أو حذف سجلاتها. تعارض تعريف قديم مفعّل حالة قبول مطلوبة، لا سبب لتجاوز حارس التعارض.
- موافقة الحذف الافتراضي ونطاق14يومًا/5000/الأسبق يوثقان من طلب المستخدم هذا؛ لا تعامل مهمة مدمرة كأنها تشغيل يدوي جديد مجهول المصدر.
- تبقى مراجعة المهام بعد استعادة/استيراد نسخة احتياطية كما هي: لا يعاد تشغيل مهام مدمرة من نسخة مستعادة تلقائيًا تحت مسمى إضافة افتراضيات.

## تعديلات إنشاء المهمة وحد الحذف

- عند الضغط على «إنشاء مهمة» يكون النوع «تلخيص الجلسات القديمة» والاسم نفسه افتراضيًا.
- عند تغيير النوع يتغير حقل الاسم إلى اسم النوع المختار تلقائيًا، ويمكن تخصيصه بعد الاختيار. فتح مهمة موجودة دون تغيير نوعها لا يطمس اسمها المخصص.
- يصبح الحد الأعلى **5000** لكل جولة حذف كروت في الأتمتة، في الواجهة والتحقق الخادمي والتنفيذ؛ ليس مجرد قيمة افتراضية يمكن تجاوزها بطلبAPI.
- المهمة الافتراضية للحذف تستخدم5000؛ التعريفات القديمة الأعلى منه تحتاج ترحيلًا موثقًا إلى الحد الجديد دون تشغيل أو زيادة نطاق الحذف.
- هذا الحد يخص مهام حذف الكروت في الأتمتة؛ لا يغير ضمنيًا حد محرك التلخيص أو إعدادات حذف صفحة الصيانة اليدوية. لا تكرر الجولات داخل موعد واحد لتجاوز5000.

## اختبارات القبول المضافة

- التثبيت الجديد والترقية والتكرار والتزامن: ستة تعريفات صحيحة مفعلة بلا ازدواج، مع الحفاظ على تعديل/تعطيل/حذف المستخدم.
- صحة06:00كل3أيام و04:00يوميًا والتحويلUTC/عدن وحدود الشهر والسنة؛ أسبوعي/شهري يتزامنان في اليوم نفسه دون تزامن التنفيذ.
- عامل طويل يتجاوز موعد التالي، وضغط موارد، وإلغاء أثناء الانتظار، وانقطاع/استئناف دون تكرار أو ضياع الموعد أو تغيير فترة التقرير.
- حذف الأسبق من نفاد الرصيد/الأيام، ومرور14يومًا، وحد5000بالواجهةوAPIوعندالتنفيذ، مع حماية غير المنتهي والحالات غير المحسومة والمال والاستهلاك.
- الاسم الافتراضي وتغييره لكل نوع، والتحرير والنسخ والأسماء المخصصة، والتوافق مع الثيمات دون تغيير الهوية البصرية.
- عدم تجاوز سياسة المراجعة بعد الاستعادة أو ازدواج القواعد القديمة أو إحياء تعريفات حذفها المستخدم.
- اختبار هذه المسارات داخل الصورة النهائية بعد إصلاحpsutil؛ وجود التعريفات والجدول فيالصفحةليسدليلًاعلىالتنفيذ.
