# توحيد إشعار تصدير PDF — 30 أكتوبر 2026

طلب الإنسان توحيد بطاقة تصدير جلسات PDF مع إشعارات النظام في المكان والهوية. نفذ في مصدر 2.7.0 المحلي فقط؛ لا نشر أو تبديل حاوية أو راوتر أو قاعدة بيانات، ولا استئناف لوحة المنظومات أو المراقبات.

## التغيير

- `web/static/heavy-export.js` يستخدم `window.showToastNotification` الفعلي، داخل حاوية الإشعارات المشتركة أعلى اليسار، بدل بطاقة مستقلة بخلفية بيضاء أسفل اليسار.
- أضيف دعم زر إجراء اختياري إلى مكوّن النظام في `base.html`، بألوان الثيمين نفسها للزر، وإخفاء زر الإغلاق عند طلب ذلك فقط. الإشعارات القديمة تبقى افتراضيًا بقابلية الإغلاق ونفس سلوكها. أضيف role=status وaria-live=polite للإشعار المشترك.
- إشعار تجهيز PDF له مؤشر انتظار مشترك وduration=0؛ لا يختفي أثناء التصدير، ولا يعرض نسبة تقدم أو شريط مدة يمكن الخلط بينه وبين تقدم الملف. زر إلغاء التصدير يبقى متاحًا. بعد قبول الإلغاء يظهر «جارٍ إلغاء التصدير» إلى وصول نتيجة التصدير؛ قبول الإلغاء ليس إعلان اكتماله.
- النجاح والفشل والإلغاء النهائي تنتقل إلى إشعار النظام المعتاد. رد إلغاء متأخر لا يستبدل نتيجة التنزيل المكتمل، وزر الإلغاء يعطل أثناء الطلب لمنع تكراره ويعاد عند فشل إرساله.
- رسائل الخادم توضع بـtextContent، فلا تتحول إلى HTML داخل الإشعار. أسماء الملف/آلية تنزيله ومعرف العملية وCSRF للإلغاء محفوظة؛ لا تعديل خادم PDF أو قسمة الملفات أو حدود الذاكرة.
- صفحة طباعة الكروت المستقلة لا تحمل محرك إشعارات base؛ عند غيابه يبقى الرابط تنزيلًا أصليًا ولا ينشئ بطاقة بتصميم بديل. المسار المعتمد لتصدير PDF/Excel من قائمة حزم الكروت لم يتغير.
- تحديث cache revision لملف heavy-export.js إلى 270-export-toast-r1 في base وصفحة الطباعة.
