# ربط حذف الكروت المنتهية — قبول محلي 3 نوفمبر 2026

اكتمل الربط في المصدر الحالي محليًا. نجحت 27 حالة تكامل على MariaDB و90 اختبار انحدار معزول. لم تبن أو ترفع صورة، ولم يحدث عميل أو دومين أو مستودع بعيد أو NAS. هذه النتيجة تتقدم على فجوات [جرد المداخل السابق](DELETION_ENTRYPOINT_COVERAGE_AUDIT_20261103.md)، ولا تغير نتائج أحجام نسخة العميل السابقة.

## ما تغير

- حذف الحزمة يحتجز الحزمة والكروت داخل معاملة واحدة. الكرت المنتهي يمر عبر `purge_details` لحفظ ملخص الاستهلاك وحماية تكرار المحاسبة وإزالة التفاصيل والبيانات التشغيلية. غير المنتهي داخل الحزمة يحتفظ بسياسة التاريخ التفصيلي السابقة.
- حساب استرداد غير المستخدم يبقى حسب خصم الإصدار المثبت، دون احتساب قيمة الكرت المنتهي كاسترداد جديد. المحفظة وقيد الاسترداد والتلخيص وحذف الحزمة كلها تلتزم أو تتراجع معًا. إعادة الطلب أو التزامن لا ينتجان استردادًا ثانيًا.
- إذا كانت هناك جلسة أو محاولة دخول غير محسومة، تحفظ الحزمة والكروت وحالاتها وأهلية الاسترداد. تثبت حراسة مؤقتة لخمس دقائق لمنع دخول جديد، وتدرج طلبات الفصل المتاحة فقط؛ إعادة الحذف بعد التسوية مطلوبة. حراسة تعديل حساب أخرى لا تستبدل.
- تصنيف موحد في `services/voucher_expiry_policy.py` للإحصاء والاختيار والتحقق تحت القفل: رصيد بيانات، أو وقت/صلاحية، أو سبب آخر. انتهى اعتبار كل سبب غير quota انتهاء وقت. الأسباب الإنجليزية المعروفة تدخل نفس العدادات والفلاتر؛ السبب المجهول أو الإداري أو الفارغ يدخل `all` فقط.
- العامل يسجل `partial` والتدقيق الجزئي إذا بقي مؤجل أو تغير مرشح. المجدول لا يسجل نجاحًا كاملًا لعملية غير مكتملة. رسائل التأجيل لا تدعي وصول Stop أو إغلاق جلسة بمجرد قبول الفصل.
- حُصر نوع هدف الحذف في voucher/subscriber مع تحويل alias `card` إلى voucher؛ فقدان الكرت لا يسمح بالسقوط إلى مشترك له نفس المعرف.

## المداخل المختبرة

| المدخل | ما نُفذ محليًا |
| --- | --- |
| صيانة قاعدة البيانات all/time/quota | POST الحقيقي ثم العامل الدائم ثم قراءة نتيجته؛ مقارنة المحدد والمحذوف والعداد |
| قائمة الكروت فردي/جماعي | HTTP الحقيقي، CSRF، صلاحيات الأصل والتفصيل، alias، مالك الكرت ومنع الطلب المختلط بمالك آخر |
| الحزمة المفردة | HTTP حقيقي لحزمة مختلطة؛ الاسترداد مرة واحدة والتاريخ المالي مطابق |
| الحزم الجماعية | HTTP الحقيقي؛ حذف حزمتين، رفض معرفات غير صالحة قبل الأثر، ومنع ملكية أخرى |
| المجدول | `_scheduled_automation_rules_job` ثم القواعد الحقيقية: quota وtime وall الافتراضي؛ مرة واحدة عند الاستحقاق |

اختبرت أسباب الصلاحية ووقت الاتصال والبيانات العربية والإنجليزية والإدارية والفارغة، وتطابق Python مع MariaDB لـ32 قيمة. سياسة عمر المجدول **لم تتغير**: `expires_at < NOW()-INTERVAL max(60,days) DAY`. اختبر إبقاء NULL والمستقبل و59 يومًا، وحذف المؤهل 70 يومًا. هذا عمر تاريخ الصلاحية، وليس وقت نفاد الرصيد؛ لا يدعى أن كل كرت منتهي بالرصيد سيدخل المجدول بعد 60 يومًا من النفاد.

## المال والتسوية والاستعادة

- استرداد الموزع الحالي: 40 من خصم إصدار 100 لحصة كرتين غير مستخدمين من خمسة؛ الرصيد 20→60، مع بقاء قيد الشراء والمبيعات دون تغيير. الموزع القديم: استرداد 30، رصيد 20→50.
- محاولة حذف متزامنة: نتيجة حذف واحدة وأخرى missing، واسترداد واحد. تعذر التفاصيل بعد أول purge، وخطأ محقون بعد SQL الاسترداد، يرجعان المحفظة والقيد والكروت والتلخيص دون أثر جزئي.
- الجلسة المفتوحة وحراسة التجديد والتاريخ الناقص تؤجل الحذف. اختبر إعادة المحاولة بعد Stop اصطناعية داخل قاعدة المختبر؛ ليس ذلك إثبات فصل راوتر فعلي.
- لكل كرت مؤهل مختبر: لا صفوف في مخازن الجلسات الأربعة أو credentials/auth/outbox/reservations؛ ملخص جلسة واحدة مطابق. aliases وUID seals وملخص الاستهلاك والسجل المالي باقية عمدًا، وليست تفاصيل جلسات متروكة.
- إنشاء نسخة فعلية واستعادتها بعد حذف المداخل: 11 جدولًا للكروت والمبيعات والفواتير والمحافظ والحزم والمصادر المالية متطابقة بالبصمة. ملف البيانات الاصطناعية 36,970 بايت، والنسخ والاستعادة معًا 10.21 ثانية؛ **ليسا تقديرًا لزمن أو حجم نسخة العميل**.
- أول اختبار استعادة كشف استكمال `global_seq_id` للكروت و`first_activation_voucher_id` للمبيعات الاصطناعية التي أُنشئت دون تهيئة هذه الحقول. المقارنة مع SQL النسخة حصرت الفرق فيهما، دون تغير أي قيمة مالية أو فقد/إضافة سجل. بعد التهيئة نجحت مطابقة الجداول كاملة في دورة نسخ واستعادة جديدة. لم تُعَد أي عمليات حذف أو استرداد ناجحة لغرض إصلاح أداة المطابقة.

## القيود الباقية المقصودة

الجلسات المفتوحة، الإغلاقات غير المؤكدة، حجز الدخول، حراسة تعديل الحساب، تاريخ ناقص/متعارض أو عدادات متأخرة فوق seal تؤجل الحذف. أكثر من 5,000 صف تفاصيل لكرت واحد يؤجل لمعالجة مجزأة؛ لم يُنفذ عامل التجزئة بهذا التغيير. أسباب غير معروفة لا تخمّن كوقت أو بيانات. لا إزالة للحماية للحصول على حجم أصغر.

حذف الباقة يرفض الارتباط بالكروت/الحزم أصلًا. حذف المشترك الحقيقي يبقى تاريخًا تفصيليًا؛ عدلت رسالة التأجيل المشتركة فقط. الاستيراد البديل والتراجع عن الاستيراد وإعادة المصنع عمليات مختلفة، لم تربط بحذف المنتهي ولم تختبر هنا.

## الأدلة والتكرار

المرجع المحمي `PRIVATE/deletion-paths-local-20261103-r4`: `RESULT.private.json` النهائي 27 حالة، و`RESTORE-COMPARE.private.json` ومرجعا الاستعادة النهائيان وبيان المصدر وملف الإغلاق.
