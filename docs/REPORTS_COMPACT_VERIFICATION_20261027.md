## ما تغير

استبدلت أرشفة كل تحديث بثلاثة جداول إضافية: wisp_traffic_checkpoints لآخر قراءة لكل جلسة، وwisp_traffic_rollups لملخص كل ربع ساعة/نقطة اتصال/مالك، وwisp_traffic_rollup_state لمؤشر الاستكمال وجيل التاريخ ووقت بدء الرصد. الأرباع داخلية لدعم حدود الساعات في المناطق ذات إزاحة ربع ساعة؛ العرض اليومي 24 ساعة والأسبوعي 7 أيام والشهري عدد أيام الشهر والسنة 12 شهرًا. لا تريغرات محاسبة جديدة ولا كتابة في radacct أو المال أو حسابات المشتركين من الجامع.

تحديث الملخص ونقطة الاستكمال في معاملة واحدة. قفل جامع خاص بقاعدة البيانات يمنع عاملين متزامنين؛ استكمال بمفتاح radacctid على دفعات 1000، بحد خمس دفعات ثم استكمال سريع بدل إسقاط ما بعد 5000. تحفظ نقطة القراءة للجلسة المفتوحة، وتحذف نقطة الجلسة المغلقة/المفقودة بعد خروجها من نافذة 48 ساعة؛ ملخص التاريخ يبقى. أول قراءة للجلسة السابقة لجيل الرصد خط أساس فقط. الجلسة الجديدة بعد بدء الرصد والتي لا تتجاوز خمس دقائق تحتسب من صفر Start حتى إن انتهت بين جولتي جمع؛ إذا تأخرت القراءة أكثر فلا يخمن توزيع الفترة.

القراءة للرسوم تجميع SQL للملخصات؛ لا تحميل لكل تحديث إلى ذاكرة Python. لوحة التحكم تشترك مع رسم الاستهلاك في المصدر نفسه. إصلاح النطاق المخصص ذي بداية دون نهاية ليصل إلى اليوم، مع إبقاء البداية المستقبلية على تاريخها.

النسخ الأصلية تشمل الجداول الثلاثة مع علامة الجيل في إعدادات النظام. استعادة نسخة ناقصة أحدها تصفر مجموعة الملخصات ونقاط القراءة معًا. إذا أعادت Web قديمة نسخة قديمة وبقيت الجداول الإضافية، فإن علامة الجيل المفقودة تمنع عرضها وتعيد تهيئتها عند العودة للجديد. هذا يمنع عرض استهلاك أحدث بعد استعادة بيانات أقدم. مسار إعادة المصنع يشمل الجداول الثلاثة.

## قياس الحجم الفعلي

الأرقام تخص جداول الاستهلاك الثلاثة فقط في تفريغ SQL مضغوط gzip، وليست كامل نسخة النظام ولا عدد ملفات النسخ المحتفظ بها. النموذج الاصطناعي الأخير يستخدم عدادات وأعداد ملاحظات متفاوتة لتجنب المبالغة في فائدة ضغط الأرقام المتكررة.

تفريغ 30 يومًا قبل الضغط 5823695 بايت؛ متوسط قراءة رسم الشهر عبر عشر قراءات 0.0435 ثانية في المختبر. حجز InnoDB للجداول والفهارس نحو 20.2 MiB بعد 30 يومًا؛ الحجم الفيزيائي يتأثر بتخصيص الصفحات ولا يساوي حجم الملف المضغوط. القياس الأول بنمط أرقام أكثر تكرارًا كان أصغر، لذلك نعتمد قياس العدادات المتفاوتة هنا. بالمقارنة بتقدير الطريقة السابقة نحو 28 MiB **نموًا يوميًا** لنموذج 1000 جلسة مستمرة وتحديث 180 ثانية، النمو الإضافي المقاس هنا نحو 25.2 KiB يوميًا لـ12 مجموعة ثابتة، مع تكلفة أولية للقراءات. لا ضمان لنفس الحجم لدى كل عميل؛ يزيد بعدد مجموعات النقاط/المالكين وتبدل الجلسات. لا ضغط أو حذف لسجل المحاسبة الأصلي لتصغير النسخة.

## أدلة التشغيل والتحقق

- 74 حالة Python معزولة ناجحة في Linux داخل صورة Web المحلية، وفحص JavaScript ناجح للأنواع/القيم/الثيمين/المجهول. محاولة Windows الأولى واجهت غياب tzdata من بيئة الاختبار؛ أعيدت داخل بيئة Linux الداعمة للمناطق الزمنية دون تغيير بيئة المضيف.
- سبعة عقود MariaDB للقراءة فقط في tests/run_dashboard_reporting_lab.py على علاقات افتراضية: تقارن أساس الرسوم الجديد، ولا تعيد اختبارات نسبة إجمالي الجلسة إلى يوم بدايتها بوصفها عقدًا جديدًا.
- جولات MariaDB الأصلية تختبر الترحيل المتكرر، المعاملات، الاستكمال، النسخ والاستعادة والرجوع. كل جولة جديدة بقاعدة مؤقتة وشبكة داخلية وحاويات موسومة؛ الجولات المكتملة لا تعاد.
- نجحت حزم radclient فعلية إلى Core مثبتة محليًا: Access-Accept وStart/Interim/Stop، مع سجل SQL مغلق واحد بعدادي 64 بت 4294967619/8589935047 وبقاء الرصيد 17.25. أثناء قفل جدول الملخصات انتظر جامع التقارير، واستمرت المصادقة والمحاسبة، ثم استكمل الجامع بعد فك القفل. هذا إثبات SQL مع الحزم، وليس ACK وحده.
- نجح الانتقال HTTP بين Web المنشورة 2.6.8 والمصدر الجديد والرجوع للقديمة. هوية Core ووقت بدء تشغيلها ثابتان. ترخيص المختبر اصطناعي؛ لا اتصال براوتر أو ترخيص ناشر فعلي.
- الأدلة الخاصة تحت PRIVATE/compact-traffic-20261027-r1 إلى r4، وبخاصة SIZING.private.json وcompact.private.json وresilience.private.json وPUBLIC-TESTS.private.txt وإيصالات التنظيف. لا بيانات دخول أو سجلات خام في Git.

## حدود النتيجة والخطوة التالية

الفروق تنسب إلى نهاية فترة القياس، وحد منتصف الليل المطابق تمامًا يغلق الفترة السابقة. لا يمكن معرفة وقت مرور كل بايت داخل الفترة بين تحديثين؛ الدقة مرتبطة بتحديثات المحاسبة، وبحد خمس دقائق في هذا الجامع. قراءة واحدة قديمة أو فترة ناقصة أو عداد متناقص لا تصبح استهلاكًا دقيقًا أو صفرًا. التاريخ التفصيلي الجديد يبدأ مع تشغيل الرصد؛ لا يعاد اختلاق توزيع ساعات الجلسات التاريخية. جداول إجمالي الجلسات/أعلى المستهلكين تحتفظ بعقد إجمالي الجلسات التي بدأت في الفترة، فلا يقارن رقمها بالتوزيع الزمني الجديد دون مراعاة الأساس المختلف.

اختبار 30 يومًا سعة اصطناعية، وليس تشغيلًا متواصلًا لمدة شهر. لا ادعاء اختبار RouterOS حي أو كل معاملة مالية أو حصة CPU مطابقة لـmax1. النسخة النهائية المترجمة والمختومة لـ2.6.9 ومسار OTA لها لم يختبرا لأن هذه الجولة لا تبني أو ترفع إصدارًا. الخطوة التالية تجميد الملفات المطلوبة من المصدر الصحيح وتجهيز صورة 2.6.9 واختبارها محليًا قبل أي قرار نشر مستقل.
