# تعديل مشترك الكرت: القبول والتطبيق المحلي، 24 أكتوبر 2026

تلت هذا البناء جولة مفوضة على NAS فعلي بالخدمتين Hotspot وPPPoE؛ [نتائجها المالية والمحاسبية وحدودها والتنظيف](REAL_NAS_ACCEPTANCE_20261024.md). وصف محاكاة NAS أدناه يخص اختبارات البناء السابقة، ولم يتغير المرشح في جولة الفحص الفعلي.

اكتمل التنفيذ والاختبار ثم بناء Web وCore وتطبيقهما على Docker المحلي، المنفذ5090، بتفويض الإنسان. لا رفع Git/Registry ولا تحديث دومين أو عميل، ولا تعديل NAS أو ربط الترخيص. نتائج هذه الوثيقة تخص المصدر المجمد والصورتين أدناه؛ ليست ضمانًا لجميع البيئات أو المسارات.

## السلوك المنفذ

- تبويب التعديل يحفظ اسم المستخدم وكلمة المرور وربط MAC وتاريخ الانتهاء الدقيق حسب الصلاحيات. الباقة والحالة تعرضان للقراءة؛ تغيير الباقة عملية مستقلة تستخدم العملية الموجودة مع خيار ترحيل المتبقي وبداية دورة جديدة للكرت المستخدم. الكرت غير المستخدم يحتفظ بحالة عدم الاستخدام دون تفعيل أو بيع مبكر، والمستهلك للشحن يرفض التعديل.
- تحفظ الهوية الثابتة للكرت عند تغيير الاسم: الجلسات الحالية والمستوردة والمؤرشفة ترتبط بالمعرف، بينما اسم المستخدم الوارد في حزمة المحاسبة وUID والعدادات تبقى كما هي. الأسماء السابقة محجوزة، وحزم المحاسبة المتأخرة تربط بالحساب الحالي دون مضاعفة الاستهلاك. المبيعات تسترجع بمعرف الكرت ولا يعاد كتابة اسم البيع التاريخي.
- تعديل الاسم أو الربط أو الانتهاء يحتاج التسوية عندما توجد جلسات؛ قبول الفصل لا يعادل Stop. كلمة المرور تحدث RADIUS والكرت في المعاملة نفسها، ولا تنشئ دورة أو بيعًا. PIN المستقل يحفظ، والمرتبط بكلمة المرور يتبع تعديلها.
- المراجعة تمنع حفظ نموذج قديم فوق تغيير أحدث. معرف العملية وبصمتها يمنعان تكرار البيع/التعديل عند إعادة الطلب. تبقى CSRF والملكية والصلاحيات والترخيص نافذة. سجل واحد بالحقول المتغيرة، دون كلمات المرور؛ لا سجل تعديل وهمي عند حفظ القيم نفسها.
- تتضمن Web أيضًا إصلاح فاتورة محفظة المشترك وتنسيق سجل التعديلات السابقين؛ فاتورة الشراء جزء من معاملة الخصم والعقد وRADIUS، وفشلها يعيد المعاملة. لا فواتير رجعية.

## المخطط والمداخل

`services/voucher_edit_service.py` و`web/routes/vouchers.py` و`web/static/voucher-edit.js` وقالب `active_card_user_details.html`. الباقة عبر `quick_action_service.action_change_package`، والهوية في `database/subscriber_edit_schema.py` المثبت المشترك مع المشتركين.

أضيف `wisp_voucher_names` و`wisp_voucher_edit_receipts` و`account_voucher_id` إلى تاريخ المحاسبة الحالي والمؤرشف والمستورد. قراءات الملكية عبر views المنتهية بـ`_owned`؛ الحزم الأصلية لا تتغير. يتجنب مثبت المخطط الفهرس الفريد على voucher_id في جدول المبيعات؛ التجديدات المتعددة مطلوبة. استعادة نسخة قديمة تنظف بيانات الملكية والإيصالات التي لا تتضمنها النسخة، مع فصل مسح بيانات الكروت عن بيانات المشتركين.

عند التشغيل المحلي تغيرت تعريفات خمسة تريغرات متوقعة فقط: تريغر ملكية المحاسبة، وحارسا إدخال/تعديل أسماء المشتركين، وحارسا إدخال/تعديل أسماء الكروت. بقية التريغرات ثابتة. Core يستعمل قراءات الملكية القائمة؛ تحققت مطابقة ملفاته الأربعة للمصدر المجمد.
