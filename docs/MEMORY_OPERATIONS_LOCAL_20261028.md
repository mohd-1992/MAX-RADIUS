# قياس العمليات الثقيلة محليًا — 28 أكتوبر 2026

## النتيجة والنطاق

طلب الإنسان قياس الأثر الفعلي لبقية عمليات التصدير والاستيراد، بعد ثبوت حادثة PDF الجلسات، وإدراج المعالجة ضمن 2.7.0. لم ينفذ هذا العمل إصلاحًا للمنتج أو بناء صورة أو نشرًا أو تغييرًا لأي دومين. مراقبة خادم الدومينات السابقة تبقى PAUSED.

ثبت OOM مستقل في PDF الكروت ضمن العدد المسموح حاليًا. ثبت أيضًا تضاعف استهلاك Excel عند التزامن، وبطء شديد في Excel الكروت، وتأثر محلل SQL بطول العبارة الواحدة. الاستعادة الحالية على MariaDB كانت أفضل في ذاكرة التنفيذ في العينات المقاسة، وليست ضمانًا لكل نسخة أو حمل.

الأدلة والبرامج والملفات المصطنعة تحت الإحالة المحلية المحمية `PRIVATE/memory270-local-20261028-r1`؛ ليست ضمن Git أو الصور. المرجع السابق لحادثة الجلسات: [M_SESSION_EXPORT_OOM_20261027.md](M_SESSION_EXPORT_OOM_20261027.md).

## منهج القياس

- المصدر الحالي مركب للقراءة فقط في `/src`، مع بصمات سبعة ملفات قبل استكمال الجولة وتحقق أنها لم تتغير بعدها. الصورة المحلية `c5ab9fe42359` استُخدمت لتوفير Python 3.11.17 وopenpyxl 3.1.5 وChromium/Playwright؛ هذا اختبار المصدر الحالي، وليس إثبات تطابق كل ملف مع المصدر المترجم داخل الصورة المنشورة.
- حاوية مستقلة لكل قياس: 2 CPU، و2GiB RAM، وRAM+swap إجمالًا 2GiB؛ لا swap إضافي. لا منافذ منشورة. الاختبارات الصرفة `network=none`؛ اختبارات MariaDB على شبكة داخلية جديدة لا تضم غير حاويات الجولة.
- MariaDB اختبارية جديدة، بحد1GiB وbuffer pool قدره128MiB. لا نسخ قواعد عملاء أو اتصال بخادم الدومينات أو NAS أو مصادقة اختبارية. اسم قاعدة الاختبار وهويتها مثبتان في البرامج الخاصة.
- كل البيانات مصطنعة. جداول المصدر أنشئت داخل قاعدة الاختبار، ثم استُكملت جداول الأرشيف والملكية اللازمة عبر مثبتات المصدر. لم يُستورد `web.app` ولم تبدأ عمال التطبيق.
- أخذ عينات `memory.stat:anon` و`memory.current` كل50ms داخل حاوية التنفيذ. الجدول يعرض MiB، وليس MB. `anon` يستبعد كاش الملفات؛ إجمالي cgroup يشمل الكاش وبعض المصروفات الأخرى. القيم ذرى تقريبية مقاسة للحاوية كلها، وليست زيادة صافية فوق خدمة Web عاملة. عند اختبارات DB قيس استهلاكها منفصلًا؛ الأرقام تتضمن خطها الأساسي والكاش الدافئ من الاختبارات السابقة.
- المهلة المختبرية240ثانية، وليست مهلة يفرضها المنتج. فُصل فشل/قتل عامل الاختبار عن نجاح مشرف القياس؛ خروج حاوية المشرف بصفر لا يحول فشل العملية إلى نجاح.
- فحوص الترخيص وإتاحة الميزة محاكاة داخل عملية الاختبار فقط لقياس التنفيذ بعد السماح؛ لم تُعدل تراخيص مخزنة أو مفاتيح أو مراجع ثقة. هذه ليست اختبارات قبول للترخيص أو لمسار HTTP الكامل.

## تفسير النتائج

1. **PDF الكروت خطر مثبت، لا احتمال نظري.** العدد2000مسموح في المصدر الحالي؛ تعقيد القالب وQR وتخطيط الطباعة يغير الذروة كثيرًا. الحد العددي وحده لا يكفي، والقفل `_PDF_SLOT` محلي لعمليةPython؛ كما أن تجهيز HTML يحدث قبل الحصول عليه. فحص حد2000في المسار يأتي بعد جلب الكروت وتجهيزHTML.
2. **Excel الكروت يعاني مشكلة زمن مستقلة.** `make_workbook` يستدعي `ws.max_row` داخل حلقة كل خلية. تطبيق الخاصية فيopenpyxl3.1.5 يفحص مفاتيح الخلايا المتراكمة؛ تفسر قياسات500/1000/2000النمو الشديد. لا نستنتج ذروةRAM كاملة لتصدير20000لأنه لم يكمل المهلة.
3. **Excel المبيعات وقراءة Excel يراكمان الذاكرة.** المصنف العادي وقوائم الصفوف ونسخ المحتوى تبقى فيRAM. التزامن ضاعف الذروة تقريبًا. عدد الصفوف والأعمدة ومحتوياتها وتنسيقاتها كلها مؤثرة؛ حجم الملف المضغوط وحده لا يحددRAM.
4. **الاستعادة ليست مكافئة للاستيراد الخارجي.** مسارMariaDB الحالي يستخدم ملفات مؤقتة وعميلًا أصليًا، ونجح في العينة الكبيرة دونOOM. يظل يحتاج وقت قرص وذاكرةDB وكاش ومساحة مؤقتة. مسارSQLite المختلف لم يُقَس في هذه الجولة.
5. **المحلل الخارجي حساس لطول السطر.** يقرأ تدريجيًا على مستوى الأسطر، لكنه ينسخ ويفصل العبارة كاملة. النتيجة426مقابل24MiB لنفس عدد الصفوف تثبت أن التقسيم الحالي لا يضمن استهلاكًا ثابتًا. الترحيل المقاس بعبارات500صف و10000هوية كان أفضل؛ لا تعميم على500000هوية مختلفة أو dump بسطر ضخم.

## ملاحظة جانبية مثبتة في الاستيراد

ظهرت محاولة20000كرت دون أرقام تسلسلية مقدمة اصطدمت بأرقام مولدة تلقائيًا، وفشلت بقيد `idx_voucher_serial`. المصدر يولد جزءًا عشوائيًا من8أرقام دون حجز/تحقق يمنع التصادم داخل الملف. هذه ليستOOM. لحساب ذاكرة المسار الناجح استخدمت عينة مستقلة بأرقام تسلسلية فريدة صريحة.

حُفظت المحاولات غير المقبولة منفصلة: بوابات ترخيص fixture، ونقص إعداد جدول أرشيف في fixture، وخطأ في استعلام تحقق المختبر بعد commit. بعد الأخير تحققنا قراءةً من20000كرت و20000حساب بدل إعادة استيراد عملية ملتزمة؛ ثم قيس استيراد عينة مستقلة بأسماء وأرقام مختلفة. لا تُعرض هذه المحاولات كنجاح ترحيل أو كأعطال إنتاجية جديدة. التصادم التسلسلي وحده ملاحظة منتج إضافية مثبتة.
