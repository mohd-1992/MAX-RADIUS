# صيانة قاعدة البيانات — عقد السلامة والتحقق

تاريخ المراجعة: 19 أكتوبر 2026. النطاق: إصلاحات صفحة الصيانة على LAB فقط؛ لا تغيير لمخطط الجداول أو إجراءات SQL أو التريغرات. لا نشر للمستودع أو Registry ولا تحديث للعميل أو الحاويات المحلية. نتيجة النشر الحية تُسجل في HANDOFF وENVIRONMENTS منفصلة عن نتيجة المصدر.

## الحذف والتاريخ

حذف الكرت المؤهل يزيل بيانات دخوله ومهمة سياسة الاتصال التي لم يعد لها حساب، والحارس المنتهي، في المعاملة نفسها. يبقى السجل المالي والمحاسبي لحماية التاريخ. عرض الدفعة يأخذ عدد كروتها الفعلي، بما فيه صفر؛ يستخدم الاستعلام اسمًا مستقلًا لتجنب تصادم عمود card_count المخزن مع ناتج التجميع.

الأرشفة وتنظيف التاريخ يحميان الجلسات المفتوحة والدورة الحالية وخطوط أساس التجديد والجلسات المغلقة بسبب اصطناعي غير موثوق. تعارض هوية صف الأرشيف يمنع حذف المصدر. تحسين الجداول يقبل قائمة ثابتة فقط، ويحد انتظار أقفال البيانات/الميتاداتا؛ لا تعني نتيجة freed_mb ضمان إعادة حجم محرك MariaDB إلى حجم بيانات الجداول.

## المحاسبة

إصلاح «جلسة تحتاج تحقق المحاسبة» قراءة محدودة، ولا يكتب acctstoptime. لا يؤكد الإكمال إلا غياب الهوية المطابقة من NAS ووجود Stop حقيقي مع عدادات غير متناقصة وهوية SQL ثابتة. بقاء الجلسة، غياب Stop، تعذر NAS أو تغير الهوية يعيد pending أو فشلًا واضحًا. الإصلاح الشامل لا يشغل purge_stale_zombie_sessions. لا يعد CoA ACK أو قِدم السجل إثباتًا للتسوية.

## إعادة المصنع

يحفظ المنسق نسخة استرجاعية، ويمنع العمل المتداخل عبر الأقفال القائمة، وينتظر Stop الحقيقي قبل إيقاف Core ومسح الأعمال. يشمل المسح جداول مهام السياسات وحراس التجديد ودفاتر الاستيراد الموجودة، دون إنشاء جداول جديدة. تحفظ الإعدادات والترخيص وخيارات الباقات/الموزعين وتسلسل المعرفات المتزايد.

إثبات data_reset وحالة state_archive_pending يُعتمدان مع المسح في معاملة واحدة داخل سجل الصيانة الموجود. ضياع الرد بعد commit لا يسمح بتكرار المسح. تُنقل مجلدا userman-jobs وnas-session-settlements إلى maintenance-archives/<job_id> مع بصمات SHA256 وسجل مكتمل؛ تبدأ الأعمال الجديدة في مجلدات فارغة. لا حذف للأرشيف، ولا استعادة تلقائية لقاعدة أقدم.

إذا فشلت الأرشفة بعد المسح تبقى الخدمة متوقفة وحالة الاسترداد محفوظة؛ الاسترداد يكمل الأرشفة ثم يعيد Core فقط. إذا تعذر حتى تأكيد نتيجة المعاملة تبقى الحالة للمراجعة اليدوية، ولا يعاد المسح أو التشغيل بالتخمين. فشل إعادة Core بعد المسح يسجل data_reset=true ويعيد الاسترداد الخدمة دون مسح جديد. فشل التحسين وحده يظهر تحذيرًا بعد نجاح المسح.

## الأرشفة والتلخيص في مهام الصيانة — مرشح محلي 4 نوفمبر 2026

اختيار المدة يطلب عدادًا مطابقًا لتلك المدة؛ تعذر القراءة يظهر مجهولًا، ولا يعرض صفرًا. الوضع الافتراضي ينقل التفاصيل إلى التاريخ الموحد كما كان. الوضع الاختياري يلخص جلسات الكروت المنتهية بواسطة محرك التلخيص القائم؛ عداده عدد كروت مرشحة، وتثبت الأهلية داخل معاملة وقفل كل حساب.

صفحة الصيانة تقدم مهمة `accounting-archive` في سجل المهام القائم، وتتابع النتيجة والإلغاء بعد تحديث الصفحة. الإلغاء ينهي الدفعة أو الحساب الجاري أولًا. المهام المنقطعة لا تستأنف تلقائيًا. انتهاء المهمة يخفي بطاقة التقدم مع حفظ النتيجة والإشعار مرة واحدة. صلاحية العرض منفصلة عن التنفيذ، وPOST يخضع لـCSRF وميزة الترخيص.

التلخيص الحي يقتصر على تاريخ `radacct` المحسوم القديم للكرت المنتهي؛ حد العمر لا يقل عن 48 ساعة، ولا توجد جلسة مفتوحة/حديثة أو حجز/تجديد قائم أو خط أساس أو ملكية ملتبسة. وجود تاريخ مستورد/مؤرشف أو UID منسوخ خارج المصدر الحي يؤجل الكرت: قارئ الحصة الحالي لا يعامل تلك المخازن كالمصدر الفيزيائي، وإدخالها في ملخص الحصة قد يغير الرصيد. لا تختلق تسوية لتجاوز ذلك. يحتفظ التلخيص بالكرت وبيانات الدخول والحصص والمال وبصمات UID؛ تفاصيل الجلسات الملخصة لا تبقى صفوفًا منفردة. الزيادة المتأخرة فوق بصمة محفوظة تؤجل للمراجعة بدل إسقاطها أو تكرارها.

لا تحويل إلى `COMPRESSED`، ولا تحسين جداول تلقائي أو مخطط جديد. النقل لا يضمن تقليل حجم النسخة أو ملف InnoDB؛ فراغ الصفحات قد يبقى قابلًا لإعادة الاستخدام داخل الملف. [نتيجة التجارب المحلية وحدودها](ARCHIVER_JOBS_SUMMARY_LOCAL_20261104.md) هي مرجع القبول، ولا تعني نشر التعديل على أي دومين.

## الطلبات والعرض

ثمانية مسارات POST تتطلب CSRF مركزيًا، ويضيف غلاف fetch الرمز من الجلسة إلى نفس الأصل فقط. تبقى المصادقة والصلاحيات. تُهرب قيم جدول التدقيق عند توليد HTML، وتربط أزرار الإصلاح بفهرس الصف عبر listener دون إدراج اسم المستخدم داخل onclick. GET لحالة الأرشيف/المهام لا ينشئ أو يعدل جدولًا ولا يكتب حالة انقطاع المهمة؛ التهيئة مسؤولية مسار تهيئة الإصدار القائم.

Core يضبط سجل healthcheck/Cleartext-Password المحجوز تحت قفل SQL مسمى دون زيادة السجلات عند تكرار التشغيل، ودون تعديل حسابات المصادقة الأخرى أو إضافة فهرس فريد.
