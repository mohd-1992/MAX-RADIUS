## اختيار الإصدار

مصدر البيان الافتراضي HTTPS هو نفس مستودع بيان التثبيت الرسمي. يمكن تحديد MASTER_UPDATE_SERVER_URL بمصدر HTTPS موثوق؛ HTTP أو رد غير صالح أو بيان بلا نسخة مفهومة لا يعني أن النظام محدث. يعرض الفحص عدم القدرة على التحقق ويمنع التطبيق.

يحتاج الإصدار الأحدث إلى version، وupdate_scope بالقيمة web_only، وdocker_image أو images.web بالشكل mohd777/max-radius-web@sha256 متبوعًا ببصمة Registry كاملة. لا يُقبل latest أو مرجع صورة حر من طلب HTTP. يجب أن يطابق الإصدار المطلوب نسخة البيان التي أعيد فحصها، ثم يتحقق التشغيل من APP_VERSION الفعلي والتوقيع ونفس مفتاح الناشر والترخيص وصلاحية التشغيل الحديثة. لا يكفي نجاح pull أو صحة HTTP.

release.json العام ما زال يمثل الإصدار المنشور السابق. بعد الموافقة على النشر يجب رفع الصورة المختبرة نفسها، وتسجيل digest الذي تعيده Registry، وإضافة version وupdate_scope إلى بيان الإصدار وتحديث حزمته المثبتة. Image ID المحلي ليس بديلًا عن digest Registry. لا يجيز هذا المستند نشرًا أو تغيير خادم البيان.

## التنفيذ والفشل

- التطبيق متاح لمدير superadmin فقط على Docker Linux. يبقى استيراد التطبيق ممكنًا على Windows ويُرفض التحديث المباشر هناك برسالة واضحة.
- تثبت هوية Web الحالية من HOSTNAME وDocker وlabels المشروع والخدمة. يرفض الغموض أو غياب التخزين الدائم أو تجاوز ملفات التطبيق بمربط كود.
- النسخ إلزامي؛ يستدعي create_backup الصحيح مع dispatch_notifications=False، ويفحص الأرشيف ومحتوى SQL ويحفظ البصمة قبل طلب الصورة. فشل النسخ أو Docker يوقف التجهيز دون إعلان نجاح.
- يحفظ journal خاصًا داخل storage/system_updates، بملفات ذرية وصلاحيات محدودة، وقفل بين العمليات. API التقدم يعرض الحقول العامة فقط؛ الخطة الخاصة قد تحتوي إعدادات تشغيل حساسة ولا تدخل Git أو الصورة.
- يبدأ helper من صورة التشغيل الحالية الموثوقة، مستقلًا عن عملية Web واتصال المتصفح. يبدّل الحاوية الحالية وحدها ويحفظ القديمة وطبقتها وسياسة تشغيلها وشبكاتها. يحافظ على mounts وread-only rootfs ويولد hostname جديدًا.
- لا تُعلن completed حتى تنجح صحة المرشح والتوقيع والنسخة والترخيص وlease. عند فشل المرشح تعاد الحاوية السابقة في نفس الجولة دون DB restore. ضياع رد الإنشاء يُفحص من الهوية والاسم وبصمة الصورة وعلامة الجولة، دون إنشاء متكرر أعمى.
- الحالات error وrolled_back وrecovery_required ليست نجاحًا، ولا يحوّل percent=100 وحده النتيجة إلى نجاح. الحالة المحفوظة تبقى بعد إعادة تشغيل Web. أي رجوع لاحق بعد اكتمال الجولة يحتاج فحصًا ونطاق استرداد جديدًا؛ لا تعد replay لمشغل أو علامات مكتملة.
- حد معروف في المصدر الحالي: إجراء restore يعيد الحاوية السابقة وشبكاتها وسياسة تشغيلها، لكنه لا يكرر فحص الصحة والتوقيع والترخيص والـlease الكامل عليها قبل rolled_back. لا تعتبر هذه الحالة وحدها إثبات تعافٍ تشغيلي كامل؛ يلزم التحقق اللاحق، وتقوية هذا المسار قبل اعتماده لتوزيع تحديثات إنتاجية جديدة.
