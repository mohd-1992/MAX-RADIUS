# محاكاة تحديث العميل المحلي — 25 أكتوبر 2026

## الحكم

اجتازت ترقية Web/Core من نسخة العميل الخاصة 2.6.2 إلى زوج 2.6.5 المنشور اختبارات اللقطة المحلية. **لكن الرجوع المباشر إلى 2.6.2 بعد استخدام تغيير الاسم غير آمن:** النسخة القديمة لا تقرأ ملكية التاريخ الجديدة، فتتجاهل استهلاك الاسم السابق. لا يعتمد تنفيذ حي قبل تحديد نافذة رجوع تمنع هذه العمليات فعليًا، أو تجهيز رجوع متوافق واختباره.

العمل محاكاة محلية فقط. لم يحدث تحديث أو إعادة تشغيل أو تغيير إعدادات على العميل، ولم تستأنف المراقبة الدورية. تحقق نهائي بالقراءة أكد ثبات هوية المضيف والحاويات الخمس وصورها وإعداداتها وأوقات بدئها وعدّادات إعادة تشغيلها، وبقاء الخدمات healthy.

## تمثيل بيئة العميل

- استخدمت الصور الخمس الأصلية نفسها، وتحققت مطابقة طبقات RootFS. صورة Web الخاصة a52ed5e8c2d0 أعيد تجميع أرشيفها باستخدام طبقات مشتركة مطابقة مخزنة محليًا ونقل الطبقات الناقصة فقط؛ لم تعد بناؤها من checkout. طابقت ملفات تشغيل Web الـ225 عينة العميل بالبايت.
- Core الأصلية 9d52c074f0af، وMariaDB الأصلية 7db29378d4fd بالإصدار 10.11.19، وL2TP الأصلية a7fa96b5a7a4، وAutoheal الأصلية fe88c69806c7. المرشح Web 5eda6a3450dd وCore 7bf2baa71525.
- نقلت لقطة SQL حديثة ومتسقة للقراءة، مع routines/triggers/events ودون قفل الجداول، وملفات storage/uploads اللازمة وإعدادات Core وملفات PPP وتعريفات الحاويات. لم ينشأ أرشيف أو ملف ترحيل على العميل؛ النقل إلى الملفات الخاصة المحلية عبر القراءة.
- اللقطة تحتوي 64 جدولًا و666,069 سجلًا، منها **42,419 كرتًا و179,753 سجل radacct و15,809 مبيعات**، ولا مشتركين في wisp_subscribers. هذه أرقام اللقطة الجديدة، وليست المراجع التاريخية الأصغر.
- نسخت إعدادات محرك القاعدة والتوقيت Asia/Riyadh. المعمارية x86_64، وكل المكونات الأساسية تشترك في CPU set من أربع أنوية، مع حد ذاكرة لكل حاوية يقارب ذاكرة جهاز العميل 6.6GiB.

ليست العتاد نفسه: نواة العميل 6.8.0-147-generic مقابل WSL2 6.6.87.2 في المختبر، والمضيف المحلي لـDocker نحو 8GiB. حدود الذاكرة لكل حاوية لا تعادل مجموعة ذاكرة إجمالية مشتركة بحجم جهاز العميل. لذلك أزمنة المختبر قياسات استرشادية وليست زمن انقطاع متعهدًا به أو اختبار حمل مماثلًا.

الشبكة داخلية دون منافذ منشورة. منع الوصول إلى الإنترنت وراوترات العميل. استخدم وسيط Docker مقيدًا بحاويات الجولة فقط؛ لم يوصل التطبيق إلى socket المضيف مباشرة. شغلت L2TP وAutoheal الأصليتين، لكن لا PPP أو إنترنت أو راوتر فعلي في الاختبار.

## تسلسل التجربة

المحاولة r1 كشفت فرق توقيت في إعداد MariaDB المحلية؛ أوقفت مواردها وحفظت أدلتها. أعيدت التجربة المعتمدة r2 من **اللقطة الأصلية نفسها** على قاعدة جديدة، بتوقيت الرياض الصحيح؛ لا نقل جديد من العميل للإعادة.

1. استعادة اللقطة ومطابقة بصمات الصفوف، وتشغيل تهيئة 2.6.2 الأصلية وصفحة الدخول وCore.
2. إيقاف Web المحلية السابقة وحفظها، مع استمرار Core القديمة؛ تنفيذ التهيئة من وحدات 2.6.5 المترجمة والموقعة، ثم التحقق من مخطط الملكية قبل تبديل Core.
3. مقارنة الصفوف والأعمدة الأصلية بقاعدة مرجعية مستقلة مستعادة من اللقطة. إبقاء DB/L2TP/Autoheal دون تبديل.
4. تشغيل RADIUS فعلي في المختبر على سجلات اختبار إضافية، ثم اختبار الرجوع إلى الصورتين الأصليتين على **أحدث القاعدة دون استعادة تاريخية**، وإعادة التقدم إلى 2.6.5.
5. إنشاء نسخة من التطبيق الجديد بلا إشعارات، واستعادتها في MariaDB منفصلة بالإصدار والتوقيت نفسيهما وباسم قاعدة مطابق، ثم تهيئتها والتحقق من البيانات والكائنات.

عطلت عمال التطبيق الخلفيين في مسار فحص البيانات، لتجنب انتهاء عقود أو إغلاقات Watchdog أو أعمال خارجية بسبب غياب الراوترات. لم تغير ملفات الصور الموقعة. الترخيص الأصلي لم يكن صالحًا على هوية المختبر المختلفة في النسختين؛ الاختبارات الإيجابية استخدمت حالة ترخيص اصطناعية في SQL المحلية، وليس تعديلًا لترخيص العميل أو إثباتًا لقبوله على الإنتاج.

## النسخ والاستعادة

أنتج create_backup في الصورة الجديدة أرشيفًا **30,610,747 بايت**، وSQL بحجم 125,112,041 بايت، وصفر أعضاء card_backgrounds. ثبت حد Telegram عند 45,000,000 بايت وسقف الأرشيف 5GiB، ولم يطلب أو ينفذ إرسال.

نجح مسار الاستعادة الأصلي إلى قاعدة منفصلة في نحو 23.449 ثانية، ثم bootstrap في 1.086 ثانية. لا دوال أو تريغرات مفقودة، ولا فروق دلالية في تعريفاتها بعد توحيد العرض، والعروض مطابقة. البيانات المالية محفوظة. الفروق المحددة: سجل النسخة وتدقيق إنشائها يكتبان بعد أخذ dump؛ وحالة ترخيص المختبر يعاد ضبطها؛ ومفتاح أول بيع استكمل لسجل واحد **خاص بالكرت الاصطناعي** دون تغير أي قيمة مالية أو بيع من أصل 15,809 مبيعات العميل.

هذه تجربة أرشيف التطبيق واستعادة SQL وتهيئته معزولًا؛ لا اختبار لرسالة Telegram أو لاسترداد مضيف/راوتر كامل. النسخة التشغيلية قبل نشر فعلي يجب أن تشمل أيضًا الإعدادات وطبقات الحاويات ومفاتيحها وPPP، وتتحقق مشفرة خارج المضيف.
