# قبول الحارس محليًا بعد اختبارات الأعطال — 3 نوفمبر 2026

**اكتملت قائمة الاختبارات المحلية المتبقية، واجتازها الحارس المعدل ضمن التغطية أدناه. نسخة الحارس السابقة لا تعتمد.** كشف اختبار قتل المتحكم خلل استمرار عامل الترحيل بعد استئناف Core، وأصلح في الحزمة المحلية وأعيد اختباره. لم يتغير العميل أو أي دومين، ولم ترفع صور أو ملفات أو تغيّر جهة ترخيص إنتاجية.

يتقدم هذا التقرير على [التقرير المحلي السابق](CLIENT_AS_270_FOLLOWUP_LOCAL_20261103.md) في اعتماد الحارس وحزمة المشغل فقط. تبقى نتائج البيانات والمالية والاستعادة وصور الإصدار وحدود NAS والترخيص الحقيقي في التقرير السابق و[محاكاة العميل الأساسية](CLIENT_AS_270_LOCAL_REHEARSAL_20261102.md).

## الحالة المختبرة

أنشئت جولة جديدة من مدخلات العميل المحفوظة والمثبتة بالبصمة، دون إعادة مشغل جولة مغلقة: `PRIVATE/client270-guardfault-20261103-r1`. الإحالة PRIVATE موصوفة في ENVIRONMENTS. لقطة المصدر فيها 51,432 كرتًا و317,794 سجل محاسبة؛ حسابات الاختبار وجهة توقيعها منفصلة. Docker المحلي وشبكة داخلية دون منافذ منشورة، ولا اتصال بـNAS أو جهة الإنتاج.

صور Web/Core القديمة والجديدة وMariaDB نفسها المستخدمة في التقرير السابق. الجديدة `2.7.0-20261102-r1`: Web `5455db7ca85a` وCore `10cc88946c5e`. **التصحيح خاص بمشغل وحارس التحديث اليدوي خارج الصور**، وليس تغيير كود داخل Web/Core أو بناء إصدار آخر. تبقى صور DB/L2TP/Autoheal خارج الاستبدال. المصادقة المقاسة عبر FreeRADIUS UDP فعلية، بحزم اصطناعية، وليست اعتمادًا على HTTP أو healthy وحدهما.

## الخلل الذي كشفته الجولة

عند قتل عملية المتحكم بـSIGKILL **بعد أن أبطل المثبت الأصلي lease والتزم التغيير في MariaDB**، استأنف الحارس Core، لكن عامل الترحيل المنفصل استمر بعد فقد المتحكم ونفذ تسعة أوامر SQL، بينها CREATE. كانت المحاولة محلية بالكامل، ولم تبدأ حاويتا الإصدار الجديد. أوقف العامل المحدد بالهوية للتعافي المختبري، وحفظ الدليل الأصلي في `FAULT-controller_lost.result.private.json` وملف أحداثه؛ لا يغطى هذا الإخفاق بنتائج الجولة السابقة.

أضيف في الحزمة المحلية:

- إلغاء مثبت بالـnonce والمهلة، يسجله المتحكم أو الحارس قبل استئناف Core عند الفشل.
- فحص الإلغاء والموعد قبل/بعد SQL وcommit داخل مرحلة السعة، وقبل/بعد النشر الأصلي للترخيص. الإلغاء ينهي العامل ولا يتحول إلى استثناء عادي قد تتجاوزه تهيئة المخطط.
- منع متابعة أي محاولة تحمل علامة إلغاء؛ لا إعادة DDL أو عملية مالية أو استعادة DB تلقائية. عند موت المتحكم قد يبقى journal عند MIGRATING، لكن علامة الإلغاء المستقلة تمنع replay حتى دون كتابة phase نهائية.
- لا انتظار لإيصال متحكم ميت عند إنهاء العامل الملغى. بقي إبطال lease والتحقق والنشر الأصليون كما هم، دون كتابة is_valid يدويًا أو تجاوز توقيع/هوية.
- فحص حداثة heartbeat بقراءة محدودة حتى 0.3 ثانية عند ملف عابر غير مكتمل/مفقود، مع رفض قيمة قديمة أو من حقبة monotonic مستقبلية. هذه إعادة قراءة فقط قبل التنفيذ وليست إعادة SQL.

التحقق قبل/بعد الاستعلام لا يلغي أثر استعلام التزم سابقًا، ولا يدعي إلغاء DDL جارٍ على خادم DB بأثر رجعي. لذلك يبقى الفشل حجزًا للمراجعة والتعافي الصريح، دون افتراض أن المهلة تعني عدم وقوع أثر.

## اختبارات الأعطال الفعلية

كل حالة لها journal وإيصالات محفوظة. الانتقال بين الحالات تم بعد تدقيق وتعافٍ مختبري صريح بالمثبت الأصلي، على DB نفسها؛ لم تستخدم DBrestore أو إعادة عمليات مالية. لا يجوز استعمال هذا التحضير المختبري لإعادة محاولة إنتاجية فشلت.

| الحالة | موضع الحقن والدليل | النتيجة بعد التصحيح |
|---|---|---|

| توقف DB أثناء المرحلة الحرجة | إيقاف حاوية MariaDB المختبرية نفسها بعد commit الإبطال | فشلت المحاولة وحجزت عند HOLD_TRANSITION_ABORT؛ استؤنف Core، ولم تبدأ الحاويات الجديدة، ولم تستعد DB أو يعاد تنفيذ SQL تلقائيًا. الحاجز المرصود 1.726 ثانية؛ أعيدت DB نفسها للتعافي المختبري |

| فقد الحارس فجأة | SIGKILL لحاوية الحارس المحددة أثناء الحاجز، والمتحكم حي | أكمل المتحكم المثبت والتحقق الأصليين واستأنف Core؛ رفضت أي خطوة لاحقة لأن الحارس متوقف. لم تبدأ الحاويات الجديدة |

اختبرت كذلك مهلة إيقاف الحارس بالطريقة العادية؛ تجاوز الانتظار ميزانية الحاجز، فاستؤنف Core وحجزت المحاولة دون SQL إضافي. تحفظ النتيجة منفصلة عن اختبار SIGKILL المفاجئ، ولا تعد الحالة المتأخرة اختبار قتل فوري.

ميزانية الحاجز الاسمية خمس ثوانٍ؛ أزمنة Docker والتنفيذ تضيف تأخرًا مرصودًا، لذلك ليست مهلة لحظية مضمونة مقدارها خمس ثوانٍ بالضبط. لا تشمل هذه النتيجة فقد Docker أو المضيف نفسه، أو تعطل المتحكم والحارس معًا. لا إعادة تشغيل لمضيف أو خدمات مشتركة في هذه الجولة.

القصد من عدم تضمين manifest تشغيل هو منع تشغيل سياق المختبر على جهاز آخر. ربط manifest حديث بهوية المضيف والصور والتعريفات والملفات الحالية ونافذة التنفيذ جزء من preflight عند تفويض التحديث لاحقًا، وليس اختبار أعطال محليًا متروكًا.

## ملاحظات المختبر وحدود الاعتماد

ظهرت حالات إعداد/أداة منفصلة وحفظت أدلتها: بوابة Web المحلية افتقدت علامة البدء عند إنشاء الجولة، وموضع DO 0 التجريبي سبق DECLARE فأصلح قبل استئناف Core، واختبار نشر ذري كثيف على ربط Windows لم يماثل دلالات ملفات Linux. لذلك نفذت اختبارات الملفات على /tmp داخل Linux، وسجل رفض heartbeat العابر قبل أي إجراء، وعولجت قراءة الملف دون إلغاء فحص الحداثة. اختبار heartbeat الجديد كشف أيضًا وجوب احتساب العمر **بعد انتهاء القراءة** عند إعادة المحاولة؛ صحح وأعيدت الحالات الست عشرة. هذه ليست أخطاء في الصور المنشورة أو في DB العميل.

**الاعتماد المحلي للحارس مكتمل ضمن هذه الحالات.** لم تبق من قائمة الأعطال المحلية المتفق عليها حالة غير منفذة. يبقى التحديث الحقيقي مشروطًا بطلب تنفيذ لاحق وpreflight حديث ونسخة حديثة ونافذة صيانة، ثم قبول ترخيص الجهاز والمصادقة والمحاسبة الطبيعية على NAS الحقيقي. التوقيع الأصلي للعميل اختبر offline في الجولة السابقة؛ لا ادعاء قبول ربطه بجهاز المختبر أو تشغيل NAS أو Autoheal/L2TP الإنتاجيين هنا.

الرجوع ليس بلا انقطاع، والفشل الجزئي يحتاج مراجعة صريحة؛ لا rollback ثانٍ تلقائي أو DBrestore تلقائية. حالة عامل الترحيل المستمر بعد موت المتحكم أغلقت في **الحزمة المحلية المعدلة فقط**؛ لا تعاود استعمال الحارس أو manifest القديمين من الجولات السابقة. كل الإيصالات والأحجام محفوظة، ويجب الرجوع إلى CLEANUP وFOREIGN-CONTAINERS-AUDIT قبل أي استئناف. لا replay لمشغلات الجولة.
