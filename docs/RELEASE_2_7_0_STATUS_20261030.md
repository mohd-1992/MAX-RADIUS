## الاختبارات والقياسات المسجلة

- الفحص المحدد الأخير: **132 حالة،131 ناجحة وواحدة متجاوزة** تحتاج تجهيز Docker منفصلًا. نجحت فحوص JavaScript للإشعارات وPDF ومتابعة العمليات.
- CHR فعلي على العنوان المختبري المحفوظ: **12 مصادقة ناجحة وثلاث حالات رفض متوقعة و12 سجل جلسة مغلقًا وصفر جلسات اختبار مفتوحة عند نهاية الجولة**. شمل الفصل وMAC وHotspot وPPPoE وحصة1MiB. تجهيز الترخيص اصطناعي معلن؛ ليس قبول ترخيص إنتاجي على الصورة النهائية.
- نجح التسجيل والاسترداد عند بدء خادم UNIX بعد قتل العامل في المحلي والدومين والمشترك، مع حفظ أحدث البيانات والهوية والحجم ونسخ إلزامية، دون استعادة SQL فوق حركة أحدث.
- نجحت24 معاينة: ست صفحات × الكمبيوتر/الهاتف × الفاتح/الداكن، مع تحقق انتظار طويل وتزامن ونتائج نجاح ورفض ورد غير مقروء.
- اختبار الاستعادة الكبير استخدم نسخة مضغوطة **214.28MiB**، فيها150ألف كرت و300ألف بيع و900ألف جلسة وبيانات مرتبطة. تطابقت بصمات19جدولًا. الزمن **288.981 ثانية قبل مقابل302.011 بعد**؛ لم يثبت تسريع الاستعادة. توجد قراءات للذاكرة والمعالج وI/O؛ لا تخلط انخفاض CPU العامل بتحسن زمن الاستعادة.
- أثبتت عينة الجامع انخفاض زمن عمله بنحو65–71%، وفلتر NAS للاستهلاك بنحو72%. أرقام المختبر ليست وعدًا لكل دومين. ضبط DB اختياري ومشروط بالمحرك والحمل والقرص.

لا تجمع أعداد اختبارات الجولات المختلفة باعتبارها حالات فريدة أو قبولًا للصورة النهائية. التفاصيل والفشل الأولي وإصلاحاته محفوظة في التقارير والأدلة الخاصة.

## المتبقي بالترتيب

1. **إغلاق قبول الواجهة:** إصلاح تجهيز اختبارات ملكية SQLite القديمة وإعادة الحالات الأربع غير الناجحة؛ ثم قبول تنزيل الملفات الفعلي وإلغائها والفشل المتأخر والصلاحيات والتزامن في المتصفح. نجاح معاينات الصفحات وحده لا يغلق هذه المرحلة.
2. **إغلاق القبول الحي والمحاسبة:** عزل ملاحظة `NAS-Reboot` لسجل Hotspot ظل متصلًا أثناء التهيئة الأولى لـPPP/RADIUS، مع التقاط Accounting-On/Off منذ البداية. إعادة تعطيل خادم PPP الاختباري وتشغيله لم تكرر الأثر؛ السبب الجذري غير محسوم، ولم تتغير استعلامات Core لمعالجته. استكمال عدةNAS فعلية وFastTrack بمرور حقيقي والفشل الجزئي وتداخل التجديد/نفاد الحصة والحزم المتأخرة.
3. **إكمال تسليم المحرك:** ربط ناشر العروض والقناة وواجهة إدارة الحزمة، وتجهيز خطة مخطط2.7.0 وتوافق إصدارات المكونات والثقة والترخيص. لا اعتماد لتوزيع محرك تجريبي لمجرد نجاح نواته محليًا. استكمال قياس11.8 إذا كان ضمن الصور المستهدفة؛ لا تعميم ضبط10.11 عليه.
4. **بناء صورة2.7.0 النهائية:** من المصدر الصحيح والتبعيات المثبتة، ثم قبول التحديث والرجوع مع أحدث البيانات والترخيص، واستعادة النسخ القديمة والكبيرة على الصورة نفسها. استكمال مسار HTTP ومهل الوكيل؛ البناء المحلي السابق2.6.9 ليس صورة2.7.0 النهائية.
5. **قبول موارد ممتد:** جمع الرصد والتقارير والتصدير والاستيراد/الاستعادة والمحاسبة بحمل متغير ومتزامن، ثم خمول؛ قياس الذاكرة وCPU وI/O وPSI وOOM والأقفال والمؤقتات، وإثبات التنظيف وعدم النمو المستمر.
6. **التسليم النهائي:** إغلاق الموانع، مراجعة الحزمة وملاحظات الإصدار وخطة الرجوع، ثم موافقة نشر مستقلة تحدد البيئات والدومينات. لا نشر تلقائي أو تحديث عميل ضمن طلب التوثيق الحالي.

النقاط1–3 من قائمة القبول السابقة **نُفذ منها جزء كبير لكنها لم تُغلق بالكامل**؛ النقاط4–6 ما زالت لاحقة.
