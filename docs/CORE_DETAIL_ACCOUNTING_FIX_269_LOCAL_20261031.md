# إصلاح تسجيل محاسبة Core — 2.6.9 محليًا، 31 أكتوبر 2026

**النتيجة: نجح إصلاح مشكلة أول Accounting-Start وفصل السجل التشخيصي عن حفظ SQL في الاختبارات المحلية المحددة.** نجحت 36 حالة للجولات الباردة وأعطال السجل، و20 حالة للتعافي والتكرار والرجوع، و10 فحوص لعمليات الواجهة. لم يجر رفع أو تحديث عميل أو دومين أو تغيير latest.

## الحزمة المحددة

- Core الأساس: `sha256:7ffa03b73990e25f8e10b72eb8e29dd446e2ffb2942ec8df2599e539f37cb7c5`.

التعديل الجديد يخص **Core**. الحزمة المحلية الكاملة أصبحت Web المذكورة وCore النهائية، مع بقاء DB وL2TP وautoheal دون صورة جديدة. Core الجديدة تحفظ إصلاح Accounting-On/Off السابق؛ SQL المحاسبة نفسه وملف daemon متطابقان مع الأساس. صور r1–r5 تمهيدية مستبعدة من التسليم، ولا تستخدم كبديل للهوية النهائية.

## السبب والإصلاح

كانت وحدة `detail` تنشئ مجلدًا فرعيًا لكل عنوان مصدر عند أول حزمة. قد تتنافس الطلبات على إنشائه؛ يرجع أحدها fail بسبب EEXIST، ويوقف الإعداد القديم المحاسبة قبل SQL. [قبول الأقفال السابق](ACCOUNTING_ROW_LOCK_FIX_269_LOCAL_20261031.md) فصل هذه المشكلة عن SQL1213.

الإصلاح ثلاثة أجزاء:

1. مجلد أب ثابت يجهز مرة قبل بدء العمال، باستخدام إنشاء آمن إن لم يكن موجودًا. الملفات منفصلة لكل مصدر ويوم داخل ذلك المجلد؛ المصدر عنوان الحزمة الفعلي، وليس نصًا يختاره المشترك. لم تُحذف المجلدات أو الملفات القديمة ولم يجر تغيير صلاحيات الموجود منها تلقائيًا.
2. `detail { fail = 1 }` يسمح بمواصلة المحاسبة إلى SQL عند فشل الملف التشخيصي. **سياسة فشل SQL لم تُخفف**؛ لا يكفي نجاح ملف النص لإرسال رد محاسبة عندما يفشل حفظ SQL. الآلية موصوفة في [توثيق FreeRADIUS الرسمي](https://wiki.freeradius.org/config/Fail-over)، وأثبتت هنا بالحزم وقراءة SQL.
3. كشف اختبار ENOSPC أن الوحدة الأصلية تتجاهل نتيجة `fclose` الذي يفرغ الكتابة المؤجلة. رُقعت الوحدة نفسها لفحص النتيجة، وإظهار RERROR ثم تحرير القفل وإرجاع fail عند فشل التفريغ/الإغلاق. بذلك تبقى المحاسبة في SQL ويظهر عطل التخزين، دون كاتب إضافي أو ملف تحقق متنامٍ أو عملية فرعية لكل حزمة.

ملفات المصدر: `docker/freeradius/entrypoint.sh` و`detail` و`patches/detail-close.patch` و`patches/build-detail.sh` وDockerfile الخاص بـCore. الوصفة تبني وحدة التسجيل فقط في مرحلة مستقلة، ولا تضيف مترجمًا إلى runtime. مصدر Debian وهويته وABI مثبتة على FreeRADIUS3.2.1+dfsg-4+deb12u1؛ هذا رقم محرك FreeRADIUS، لا رقم إصدار MAX. تحفظ الصورة مصدر الوحدة المرقع ورقعتها مع إشعار GPL الأصلي.

## حدود النتائج وتصحيحات أدوات الاختبار

- المهلة لا تثبت عدم الالتزام: في تجربة انقطاع DB استطاع طلب محاسبة معلّق أن يلتزم بعد عودتها قبل تحقق المشغل. صحح معيار الفحص ليقرأ SQL أولًا ويقبل الالتزام الوحيد الصحيح، ثم يثبت idempotency بإعادة الحزمة نفسها. لم تُعد أي عملية مالية.
- امتلاء filesystem لا يمنع الكتابة داخل نهاية صفحة ملف محجوزة سلفًا. استُبدل فحص أولي قصير بحزم تتجاوز تلك الصفحة حتى يحدث ENOSPC فعلي. ولم تُعد قيمة Class الواحدة لجلسة أخرى؛ لكل جلسة جديدة مصادقتها.
- المرشح الأول حل فقد Start، لكن اختبار التفريغ المتأخر كشف عدم ظهور الخطأ؛ لذلك استُبعد. تجربة كاتب تحقق إضافي استُبعدت أيضًا؛ النهائية تستخدم فحص الإغلاق في الوحدة الأصلية فقط.
- وقع Access-Reject واحد في محاولة تمهيدية بعد انقطاع DB؛ لم يُعزل سببه لحظة وقوعه، فلا ينسب إلى patch التسجيل. استُعيدت lease المختبرية عبر التحقق الموقّع والنشر الأصلي قبل قبول جولة التعافي النهائية؛ نجحت المصادقة والرجوع فيها. لم تغير ثقة المنتج أو جهة ترخيص إنتاجية.
- لم تُعَد هنا مصفوفة الاستعادة الكبيرة أو التصدير أو20دقيقة العمليات المالية أو اختبارات NAS المادية. قبولها السابق موثق ضمن صورها؛ لا تُنسب إلى هذه الجولة. الإصلاح المحدد مقبول محليًا، وهذا التقرير ليس ادعاء اعتماد إنتاج شامل لكل وظائف الإصدار.
