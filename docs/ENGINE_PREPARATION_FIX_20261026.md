# إصلاح تهيئة محرك التحديث — مصدر محلي، 26 أكتوبر 2026

مرحلة لاحقة بتفويض مستقل: [بناء صور التهيئة واختبار الانتقال والرجوع محليًا](ENGINE_PREPARATION_BUILD_LOCAL_20261026.md). عبارة عدم البناء أدناه تصف جولة إصلاح المصدر السابقة.

## النطاق والنتيجة

بطلب الإنسان نُفذ إصلاح المصدر بعد [اختبارات المسار القديم](ENGINE_PREPARATION_TESTS_20261026.md)، مع منع تحديث أي عميل أو دومين. لم تُبنَ أو تُرفع صورة إصدار، ولم يُنشأ إعلان أو إشعار. نشر لوحة control السابق لا يتغير بهذه الجولة. الفحوص تستخدم بيانات اصطناعية، ولا تصل إلى NAS أو ترخيص عميل أو SQL أعمال.

أضيف `services/system_update_handoff.py` لتسليم المتحكم بعد تحقق تحديث Web فقط. يثبت هوية المتحكم بالمشروع والخدمة ومصادر التخزين المسجلة، ويستخدم صورة Web المرشحة نفسها. يحتفظ بالمتحكم السابق وإيصال خاص قبل التبديل، ويتحقق من مقبس Unix وبروتوكول المحرك2 وختم التشغيل ومفتاح الناشر قبل completed. تحفظ صورة المتحكم المثبتة في Compose. حالة handoff_pending تستمر في واجهة التقدم ولا تسمح بطلب آخر.

فشل المتحكم المرشح يعيد المتحكم السابق ويتحقق منه قراءةً، دون استعادة DB أو إخفاء فشل التهيئة. تبقى النتيجة recovery_required لأن Web تبدلت ولم تكتمل تهيئة المحرك. الإيصال المقطوع أو نتيجة الإنشاء المجهولة لا يعاد تنفيذها عمياء. التعديل الخارجي لـCompose لا يُستبدل عند الاسترداد.

## سجل الفشل وإعادة المحاولة

حُفظ إصلاح2.6.5: يمكن طلب محاولة جديدة صراحةً بعد فشل مؤكد قبل تبديل الخدمات، مع إثبات خروج helper بنجاح وتطابق الهوية والخطة وحفظ سجل الجولة السابقة. أضيف منع تجاوز عامل سابق ما زال يعمل بمجرد اختيار إصدار مختلف. لا يُحذف سجل الفشل لحل الحظر، ولا يسمح للسجل المجهول أو محاولة بدأت التبديل بأن تتحول إلى إعادة آلية. حالات rolled_back وrecovery_required ليست نجاحًا.

## متطلبات القناة والتغليف

أضيف قارئ محلي للمتطلبات الموقعة: بروتوكول المحرك، منصة Linux الفعلية، مراجعة مخطط مثبتة من إعداد المضيف الموثوق، وخطة صور رجوع متوافقة. المراجعة المفقودة مجهولة وتمنع الحزمة المحروسة؛ لا تُخمن من رقم التطبيق. يتحقق التجهيز من تطابق digest الرجوع الموقع مع RepoDigests للصورة المحتفظ بها قبل التبديل.

البروتوكول2 هنا يدعم تسليم المتحكم وفحص المتطلبات؛ **لا يعلن قدرة migration ولا ينفذ SQL صريحًا**. خطط SQL وforward_only تبقى مرفوضة. أُكملت قاعدة COPY الناقصة لـdatabase/traffic_history_schema.py في Dockerfile، لكن لم تختبر صورة بناء نهائية في هذه الجولة.

## قبل الإرسال

الـhelper القديم يبدأ من صورة Web القديمة؛ لا يكتسب هذا الكود من صورة مرشحة لمجرد سحبها. لذلك يلزم مسار مرحلي: Web جسر متوافقة تحمل العامل الجديد، ثم طلب Web تالٍ يشغّل العامل الجديد ويسلم المتحكم. يلزم بناء صور تهيئة مستقلة مجمدة الميزات، وتثبيت إصدارها وdigests وتوقيعها واختبارها في تركيب محلي وتركيب دومين معزولين. لا يكفي تسمية صورة2.6.6 الكاملة «تهيئة» لاستبعاد تغييرات الميزات منها.

يبقى دعم ترحيل SQL وترتيبه قبل Core وقبول الرجوع المتوافق مع سياسة MAC خارج هذا الإصلاح؛ زوج الرجوع القديم الذي قبل MAC ممنوعًا في التدقيق السابق لا يعتمد. لا تُعطى شهادة جاهزية لتحديث2.6.6 الكامل أو نسبة نجاح نشر من هذه الجولة.
