سُحبت الصورتان بالبصمة قبل إيقاف الخدمة، وطابقت Config وRootFS النسختين المختبرتين. حُفظت نسخة معاملات من قاعدة البيانات تشمل التريغرات والإجراءات، وتعريف Compose ولقطة البيانات والإعدادات، وتحقق حفظها وبصماتها خارج المضيف قبل التبديل. لا استعادة قاعدة بيانات أو إعادة تشغيل DB. نُفّذ التبديل على معرفات 4k الدقيقة دون `compose up`، وحُفظت Web وCore السابقتان متوقفتين للرجوع. ثُبتت الصورتان في Compose الخاص بـ4k. مدة مرحلة التبديل والتحقق 36.945 ثانية؛ ليست قياسًا لانقطاع خدمة المشتركين.

نجحت فحوص ما بعد التحديث:

- Web وCore تعملان بحالة healthy وصفر إعادة تشغيل. التوقيع ومفتاح الناشر وmanifest Web مطابقون للبناء المختبر، وملفات Core التشغيلية الأربعة تطابق بصمات المصدر المجمد. لم تظهر أخطاء تحميل أو Traceback في سجلات الإقلاع المقاسة.
- الترخيص والـlease فعالان. حزمة الترخيص الأصلية وبصمتا الجهاز والنسخة محفوظة؛ تغيرت فقط مواعيد heartbeat وتجديد الـlease ومؤشر الترخيص الزمني الطبيعي.
- صفحة الدخول العامة عبر HTTPS أعادت 200، وكذلك صفحات الحزم والمشتركين وتفاصيل كرت فعلي وملفا JavaScript الجديدان. ظهرت استمارتا تعديل الكرت والباقة وحقل مراجعة التزامن. كانت قاعدة 4k بلا مشتركين مستقلين، فلم تختبر صفحة تفاصيل مشترك مستقل فعلي فيها.
- فحص الربط داخل Web أعاد Core الجديدة الخاصة بـ4k، مع إبقاء الحاويات السابقة متوقفة وعدم توريث HOSTNAME قديم.
- حافظت الكروت الـ281 على كل الحقول الأصلية ما عدا استكمال `global_seq_id` الذي كان NULL لكلها. طابقت الأرقام الجديدة جدول التسلسل دون نقص أو تكرار. هذه آلية الإقلاع الحالية في `schema_healer`، وليست تسوية استهلاك أو تعديلًا ماليًا.
- بقيت سجلات المحاسبة الـ282 بكل أعمدتها الأصلية وUID والعدادات دون تغيير. لا سجلات أرشيفية أو مستوردة منفصلة في هذه اللقطة. أضيفت أعمدة الملكية وقراءات owned وثلاثة views وأربعة جداول هوية/إيصالات فارغة وفق الميزة المختبرة.
- طابقت تغييرات تريغرات حراسة الأسماء الأربعة وتريغر ملكية المحاسبة الجديد المصدر المجمد؛ بقية التريغرات الأصلية محفوظة. جداول المبيعات والفواتير والأرصدة والحصص والعقود والأدوار والمنح وRADIUS الأصلية ثابتة في المقارنة.
- بقيت قاعدة 4k و66 حاوية أخرى بهوياتها وصورها وConfig وHostConfig وmounts وحالة التشغيل وStartedAt السابقة؛ المجموع 67 حاوية محمية ثابتة. لم تُحدّث m أوmax1 أوshn أوأي عميل.

حدود المصادقة والمحاسبة الفعلية: Core جاهزة لمعالجة الطلبات، ومنفذا UDP1812/1813 يستمعان. بعد بدء Core رُصدت تسعة طلبات طبيعية مرفوضة، بلا قبول جديد. طابقت قراءة السجلات اسمًا غير موجود في الكروت أو المشتركين، وظهر الاسم نفسه قبل التحديث. لا يثبت الرفض وحده عطل مصادقة جديدًا. انتهى اتصال NAS API بمهلة TimeoutError، ولم توجد جلسات SQL مفتوحة؛ لذلك **لا يوجد إثبات لدخول ناجح جديد أو دورة Start/Interim/Stop فعلية بعد التحديث**. لم تُجر مصادقة اختبارية أو شحن أو تجديد أو فصل أو تعديل حساب لإنتاج دليل مصطنع. نتائج الراوتر التجريبي السابقة موثقة في [قبول NAS](REAL_NAS_ACCEPTANCE_20261024.md)، ولا تعوض هذا الحد في 4k.

مشكلات أداة الفحص: رفضت القراءة النهائية الأولى تنسيق Docker ذي أجزاء الثانية التسعة قبل تنفيذ فحوص التطبيق؛ صُحح محلل الوقت وأعيدت القراءة فقط. احتاجت مقارنة التريغرات المحلية تحديد UTF-8 صراحة بدل ترميز Windows الافتراضي؛ تطابقت التعريفات بعد ذلك، ولم يلزم تعديل SQL أو الصورة أو إعادة التحديث.
