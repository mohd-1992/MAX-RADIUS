# جاهزية ترخيص RADIUS عند الإقلاع

## السبب المثبت في التجارب — 17 أكتوبر 2026

تشغيل Docker للحاويات المحفوظة بعد إقلاع المضيف لا يضمن انتظار جاهزية قاعدة البيانات وفق ترتيب Compose. يبدأ عامل `RadiusLicenseLeaseWorker` من مصنع التطبيق؛ كان يستدعي فحص المخطط ثم نشر الحالة، وينتظر 30 ثانية بعد النجاح أو الفشل معًا.

سجلات الإقلاع السابق تثبت فشل الاتصال بقاعدة البيانات أثناء فحص المخطط، ثم خطأ `Capacity schema is not ready`. كانت القراءة عند uptime88.10 ثانية قبل إعادة المحاولة التالية: `is_valid=1` لكن `valid_until` منتهية منذ42 ثانية. صارت الحالة حديثة تلقائيًا في قراءة160.14 ثانية. هاتان قراءتان متقطعتان، وليستا توقيتًا دقيقًا لأول تجدد، ولا إثبات فقد طلب مستخدم. هذا يحدد خلل إعادة محاولة نشر صلاحية RADIUS؛ لا يثبت بطء خادم إصدار الترخيص الخارجي.

## التعديل المحدود

`services/license_guard_service.py:_run_radius_license_state_worker` يفحص اتصال قاعدة البيانات المحددة بـSELECT قبل فحص المخطط الحالي. الفشل يعاد بعد2 ثم4 ثم8 ثوانٍ وبحد أقصى10 ثوانٍ؛ النجاح يعيد الدورة العادية30 ثانية. لا تكرر التهيئة بعد نجاحها في العملية نفسها. لا توجد كتابة يدوية لصلاحية الترخيص أو تغيير للتريغرات أو الحسابات المالية في هذا التعديل.

نشر الحالة نفسه لم يتغير: تحقق الحزمة والتوقيع وحماية الساعة والحظر وقراءات السعة تبقى مطلوبة. صلاحية RADIUS لا تتجاوز90 ثانية أو انتهاء الحزمة إن كان أقرب. الفشل لا يمدد الحالة السابقة ولا يسمح باستعمال حالة منتهية. سياسة heartbeat الخارجي وفترة السماح بقيتا كما هما.
