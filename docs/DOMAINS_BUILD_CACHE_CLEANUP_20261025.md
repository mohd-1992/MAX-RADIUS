## الحماية والتحقق

- ثبتت هوية المضيف من المرجع الخاص وSSH بمفتاح مضيف موثوق؛ لم تغير الاعتمادات أو الثقة.
- لم توجد عملية بناء نشطة في فحص ما قبل الحذف. طابقت قراءة `buildx du` المرشحة بالمعرفات قائمة السجلات الخاصة غير المشتركة والقابلة للاسترداد، ثم أعيد فحص حالة الحاويات قبل التنفيذ.
- استخدم `docker buildx prune` مرة واحدة بقائمة معرفات محددة و`until=24h` و`type=regular`؛ لم يستخدم حذف عام للصور أو الحاويات أو volumes، ولا `--all`. خيار `--force` هنا يلغي سؤال CLI فقط؛ لا يحذف صورًا أو موارد مستخدمة. [مرجع مرشحات Docker](https://docs.docker.com/reference/cli/docker/buildx/prune/).
- بقيت **77 حاوية: 26 عاملة و51 متوقفة**، بالمعرفات والصور وحالات التشغيل والصحة وأوقات البدء وعدد إعادة التشغيل وبصمات Config وHostConfig وmounts والشبكات نفسها.
- بقيت جميع معرفات الصور ووسومها وdigests وطبقاتها كما هي، بما يشمل صور التشغيل والرجوع؛ وبقي تعريف جميع وحدات البيانات كما هو. رقم Docker الإجمالي 109 صور لا يطابق عدد معرفات `image ls` المفحوصة 110؛ قورنت المعرفات الكاملة نفسها قبل وبعد بدل تفسير فرق العد كحذف.
- تطابقت هوية وحجم وبصمة SHA-256 لـ **656 ملفًا محميًا** ضمن جرد مجلدات النسخ/الأمان وأرشيفات `/opt` وجولة الرجوع في `/var/lib/max-radius-rollout`، مع مقارنة الروابط دون اتباعها. لم يحذف ملف أرشيف أو مفتاح أو دليل رجوع.
- أكد الفحص اللاحق ثبات جميع الحاويات؛ حاويات الدومينات العاملة المزودة بفحص صحة سليمة. كانت حاوية Web مختبرية معزولة غير سليمة أصلًا قبل العملية وبقيت كذلك؛ لم ينشأ هذا الوضع من التنظيف ولم تعدل.
