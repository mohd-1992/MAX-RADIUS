# قائمة المتبقي لاعتماد الإصدار 2.7.1

> تحديث8نوفمبر: البنود أدناه قيد تاريخي من7نوفمبر وليست حالة الاختبارات الحالية. راجع [قبولr17](RELEASE_271_ACCEPTANCE_R17_20261108.md) ومرجعه المحمي للمراحل المنفذة والأدلة؛ psutil والتوقيت والعوامل والتقارير وTelegram والنسخ والاستعادة وFastTrack اختبرت بالمستويات المذكورة. لا تكرر اختبارًا ناجحًا بسبب بقاء مربع قديم فارغًا. مصفوفة التغطية والدلتا الأخيرة لم تعتمدا نهائيًا بعد.

تاريخ القيد: 7 نوفمبر 2026، بتوقيت عدن. الحالة: **غير معتمد للإرسال**. هذه القائمة تجمع طلب المستخدم الأخير مع نتائج التشخيص ومصفوفة الاختبارات، وتتقدم على أوصاف الجاهزية التاريخية.

القيد توثيق فقط؛ لا يبدأ إصلاحًا أو اختبارًا أو بناءً أو رفعًا أو تحديثًا. لا تعاد مهام إنتاج فاشلة أو مشغلات جولات قديمة لغرض الاختبار. لا يغلق بند دون دليل من الصورة النهائية أو بيئة التشغيل المطلوبة فيه، مع فصل النجاح والفشل والمحاكاة وغير المختبر.

## عيوب مثبتة وتصحيح التجهيز — أولوية أولى

- [ ] **R271-01 — تبعية psutil المفقودة.** إدراج تبعية تشغيل مثبتة بالاختبار في المتطلبات وقيود البناء ووصفة الدلتا الفعلية؛ تعديل requirements وحده لا يثبت دخولها في الصورة. إعادة البناء والتحقق من وجودها، ثم تشغيل فحص الموارد الحقيقي وعامل الأتمتة بالحماية العامة وخيار المهمة مفعّلين. لا تجاوز بفصل الحماية أو تثبيت pip داخل حاوية العميل. الحالة: عطل مثبت في ef615 وc8da، غير مصحح.
- [ ] **R271-02 — توقيت سجل الأتمتة.** إخراج وقت API بتمييز UTC صريح، وتحويل العرض إلى توقيت النظام بدل إلحاق UTC بالنص الخام. اختبار فرق +03:00 وحد اليوم والترتيب والمدد والسجل بعد تحديث الصفحة. الحفاظ على عقد UTC الخاص بمهام الأتمتة، وعدم تغيير أزمنة RADIUS أو البيانات القديمة المخزنة. الحالة: قصور عرض مثبت، غير مصحح.
- [ ] **R271-03 — قبول التوقيت وأغلفة التشغيل لكل وجهة.** التحقق من الغلاف والـentrypoint والـmounts والـbinding مع الصورة المختارة. الغلاف القديم يلغي init_command الخاص بـ+03:00؛ المصحح يحفظه ويضبط مهلة metadata بعد الاتصال. توجد أدلة تصحيح واختبارات سابقة، لكن يعاد إثبات التوافق مع الصورة النهائية الجديدة عند تجهيز كل وجهة. لا يكفي توقيت الصورة الافتراضي أو HTTP200 وحده.
- [ ] **R271-04 — بوابة تجهيز الصورة النهائية.** فحص التبعيات المباشرة والفرعية وأوامر التشغيل وملفات المكتبات المترجمة والأصول والتوقيع والإصدار والبصمة ومدخلات البناء. ربط كل إصلاح بملفه واختباره داخل الصورة الناتجة. تثبيت التبعيات المقصودة دون تحديث مكتبات أخرى ضمنيًا. تمرير pip check وحده ليس معيار قبول؛ نجح سابقًا رغم غياب psutil غير المعلنة.

## صفحة الصيانة ومحرك الأتمتة — أولوية أولى

- [ ] **R271-05 — قبول الأنواع الثمانية من البداية إلى النهاية.** تشغيل يدوي ومجدول من واجهة النظام إلى العامل الفعلي داخل الصورة النهائية، بحماية الموارد مفعلة. يشمل التلخيص والحذف والتدقيق والمؤقتات والسجلات وتنبيه المساحة والتقرير وتحسين الجداول. اختبارات المحركات السابقة محفوظة لكنها لا تغلق هذا البند.
- [ ] **R271-06 — الحذف والتلخيص وحفظ البيانات.** تغطية المنتهي كله/الأيام/الرصيد، والعمر 0 ومجهول تاريخ الانتهاء، وحد الجولة والباقات والحزم، وإعادة التحقق من الحالة والتزامن والإلغاء والانقطاع. مقارنة الأرصدة والحصص والمال والاستهلاك وبصمات منع التكرار وعدم وجود مخلفات غير مقصودة. استخدام المحركات المشتركة مع صفحة الصيانة؛ لا إنشاء منطق حذف أو محاسبة مكرر.
- [ ] **R271-07 — بقية عمليات الصيانة والتنظيف.** اختبار فحص الملاحظات وإصلاح المفرد/الكل كمسارات منفصلة، وتحسين جداول فعلية غير فارغة مع الأقفال والمساحة والفشل والإلغاء قبل SQL. اختبار مستقل لتنظيف المؤقتات وسجلات الأتمتة، وتمييزه عن تنظيف سجلات المحاسبة/المصادقة بصفحة الصيانة؛ حفظ الملفات المستخدمة والنسخ والمال وأدلة التسوية ومنع الإعادة.
- [ ] **R271-08 — الجدولة ودورة حياة المهام.** الأوقات اليومية المتعددة والفترات والأسبوعية والشهرية والمرة الواحدة، البداية والنهاية وعدد التشغيلات والمواعيد الفائتة وحد اليوم. التزامن والأقفال وإعادة الطلب وضياع الرد وإعادة تشغيل العامل والإلغاء والحذف مع حفظ السجل. اختبار قياس الموارد الفعلي في الحالة الطبيعية والمرتفعة، مع تمييز المحاكاة المستخدمة لاختبار حدود معينة.
- [ ] **R271-09 — النتائج والإشعارات والتقارير.** صحة عرض النجاح والجزئي والفشل والتخطي والإلغاء، وتنبيه المساحة عند الانخفاض والتعافي، وحفظ التقرير قبل الإرسال ومنع تكراره. استكمال قبول تسليم تلجرام الحقيقي ضمن تفويض صريح لاحق أو قناة اختبار معتمدة؛ المحاكاة الحالية لا توصف بأنها تسليم حقيقي.

تقدم محلي ضمن **R271-09** في7نوفمبر: [توحيد قالب تقارير الأتمتة مع مركز الإشعارات](RELEASE_271_REPORT_FORMAT_LOCAL_20261107.md) منفذ، و34اختبارمصدر ناجحة. البند **لا يغلق**؛ التغليف في الصورة النهائية وتشغيل العامل بالحماية وقبول النقل الحقيقي ما زالت متبقية.

## قبول النظام والتحديث — أولوية ثانية لازمة لتعميم الاعتماد

- [ ] **R271-10 — FastTrack على NAS فعلي.** Hotspot وPPPoE، متصل وغير متصل، جلسة واحدة ومتعددة، تغيير الاسم ونوع الخدمة وIP، وStop فعلي متأخر/مكرر مع حفظ المال والحصص والجيل. قبول مصادقة ومحاسبة طبيعية بعد الحفظ. NAS المحاكى واختبارات Core المحلية لا يغلقان القبول على جهاز فعلي؛ لا تجربة مالية أو فصل مشترك إنتاج دون طلب جارٍ يفوضها.
- [ ] **R271-11 — استعادة شاملة على الصورة النهائية.** استخدام نسخة العميل الموجودة محليًا، دون تنزيل نسخة جديدة ضمنيًا، ومقارنة الكروت والمشتركين والأرصدة والدفاتر والحصص والجلسات وUID والعدادات وحالة الأتمتة. إثبات تعطيل المهام للمراجعة بعد الاستعادة ومنع تنفيذ/إرسال غير مؤكد. تجارب النسخ والاستعادة القديمة محفوظة ولا توصف بأنها هذه التجربة الجديدة الشاملة.
- [ ] **R271-12 — تحمل وتزامن وموارد.** قياس الزمن وCPU وRAM قبل/بعد على البيانات نفسها، واختبار تداخل الأحمال الثقيلة مع النسخ والتصدير والمصادقة والمحاسبة والتعافي. لا تعميم قياس محرك منفرد أو نجاح حركة RADIUS أثناء تبديل Web على كل الأحمال. لا إعادة إدخال تحسين RAM ثبتت له كلفة أو لم يثبت له وفر.
- [ ] **R271-13 — عمليات الصفحات والصلاحيات.** مصفوفة تربط كل زر وطلب كتابة بالمحرك والنتيجة والاختبار: النجاح والرفض والمهلة والتكرار والصلاحيات والملكية وCSRF. فتح GET بنجاح ليس قبولًا لعمليات الحفظ والتجديد والحذف والإصلاح. فصل العمليات المالية وRADIUS عن صلاحية API وحدها.
- [ ] **R271-14 — القبول النهائي للنشر والرجوع.** بعد تصحيح الصورة: إعادة التحقق من ملفات تشغيل كل وجهة وهوياتها والترخيص وربط Core وتقدم المحاسبة، ومقارنة التحديث والرجوع مع حفظ قاعدة البيانات الحية. تحديث مراجع المنفذين والمسودتين والبصمات بعد قبولها، دون نشر أو تثبيت تلقائي. توجد اختبارات حارس ورجوع فعلية سابقة؛ لا تعاد مشغلاتها التاريخية أو تعد بديلًا لقبول المرجع الجديد.
- [ ] **R271-15 — تغطية التكامل والاستثناءات.** تمييز اختبار جهة الترخيص الخارجية الحقيقية عن الترخيص المختبري الموقع والقراءات الحية، وحسم قبول التكامل المطلوب دون تغيير ترخيص عميل ضمنيًا. مراجعة حالة اختبار legacy retry المتجاوزة وتوثيق سبب الاستثناء وصلته بالإصدار؛ لا تحسب ناجحة. لا يعاد فتح أخطاء fixtures قديمة حُسمت بالفعل على أنها أعطال منتج.

## إضافة المستخدم: المهام الافتراضية والاسم وحد الحذف

- [ ] **R271-16 — ست مهام تلقائية مفعلة وجدول غير متزامن.** حذف كل3أيام06:00بعمرانتهاء14يومًا وحد5000، تلخيص يومي04:00، تنظيف مؤقتات أسبوعي، تنظيف سجلات أسبوعي، وتقريران أسبوعي عند منتصف الليل وشهري. [تفاصيل المتطلبات ومواعيد الاستكمال المقترحة والترحيل والاختبارات](RELEASE_271_AUTOMATION_DEFAULTS_PLAN_20261107.md). غير منفذ؛ يمنع التكرار والتزامن ويحفظ اختيارات المستخدم وسياسة المراجعة بعد الاستعادة.
- [ ] **R271-17 — اسم المهمة التلقائي وحد5000.** يبدأ إنشاء المهمة باسم ونوع تلخيص الجلسات القديمة، ويتغير الاسم عند تغيير النوع. فرض حد حذف الأتمتة5000فيالواجهةوالخادم والتنفيذ، ومراجعة التعريفات القديمة الأعلى منه دون تشغيلها. لا تغيير ضمني لحد التلخيص أو حذف الصيانة اليدوي.

## مستثنى بقرار سابق

- WhatsApp مستثنى بطلب المستخدم؛ لا يوصف بأنه مصلح أو مختبر ضمن هذا الاعتماد.
- تحسينات RAM التجريبية غير المعتمدة لا تدخل الإصدار تلقائيًا.
- لا تحديث صور Core أو DB أو تغييرات ترخيص/NAS أو معاملات إنتاج أو رسائل خارجية يجيزها مجرد قيد هذه القائمة.

## ضابط الإغلاق

لكل بند: المرجع المختبر وبصمة الصورة، التكوين والبيانات، السيناريو والنتيجة الفعلية، ما حوكي أو لم يختبر، وفحص حفظ البيانات والموارد عند الصلة. القائمة لا تعني أن كل بند عطل مثبت؛ R271-01 وR271-02 عيبان مثبتان، والبقية شروط قبول أو تغطية متبقية أو تحقق نشر.
