# ثبات هوية المحاسبة عند تغيّر المنفذ

الحالة: مرشح مصدر ومختبر محلي، غير منشور على CLIENT_AS. طلب الإنسان في20 أكتوبر2026 اعتمادًا أوليًا على LAB واختبارات موسعة؛ لا يمثل ذلك قبولًا قبل التحقق الفعلي أو تفويض نشر العميل.

[نتيجة الفحوص واعتماد LAB وحدوده](ACCOUNTING_IDENTITY_RESULTS_20261020.md).

## السبب المثبت

حُفظت خصوصيًا حزمتا Start و57 حزمة Interim لحالتين. تغيّر NAS-Port-Id وحده بين مدخلات بصمة acct_unique، وأعادت البصمة المحلية إنتاج معرّفي الحزم وصفّي SQL في كل حالة. Class ثابتة بصيغة maxcap، لكن السياسة الأصلية تستعمل المسار الثابت مع ai فقط؛ لذلك استخدمت حقول المنفذ المتغيرة. هذه نتيجة للحالتين وليست تقديرًا لانتشار عالمي أو إثباتًا لعيب firmware. تفاصيل detail تأتي بعد preacct، وليست pcap من الشبكة.

## المرشح

الملف [max-accounting-identity.conf](../docker/freeradius/max-accounting-identity.conf) يعرّف max_acct_unique. تنسخه صورة Core ويضيف entrypoint استدعاءً واحدًا بعد acct_unique في default، مع إنهاء preacct عند الفشل. لا يتغير Class أو حجز السعة أو استعلامات تسوية المحاسبة.

- يطبق الفرع الجديد على Class واحدة بالضبط وبصيغة maxcap مع32 محرف hex صغيرة، وحساب ومعرّف جلسة وNAS IPv4 غير فارغة.
- يبحث باستعلام SELECT عن سجلين مرشحين كحد أقصى ضمن الحساب وNAS ومعرّف الجلسة وClass المطابقة بايتًا. فهارس username/session الحالية مسار الوصول؛ لا تغيير مخطط أو ترحيل بيانات.
- عند وجود سجل واحد يحفظ معرّفه القديم، حتى لو كان مغلقًا ووصل Stop متأخر. هذا يمنع إنشاء سجل جديد لجلسة صحيحة قائمة عند تفعيل المرشح.
- عند عدم وجود سجل يبني بصمة maxacct-v1 من بصمات الحساب وNAS وClass ومعرّف الجلسة. الحقول المتغيرة مثل المنفذ لا تدخلها؛ البصمات المنفصلة تمنع التباس الفواصل بين الحقول.
- عند تعدد السجلات يحفظ مسار acct_unique القديم دون دمج أو اختيار MAX أو أول صف؛ معالجة الانقسام التاريخي تحتاج دليلًا ومهمة منفصلة.
- عند فشل البحث أو معرّف مخزن غير صالح لا يخترع معرّفًا جديدًا ولا يؤكد الحزمة. يجب أن تعيد NAS المحاسبة وفق آليتها المعتادة.
- غياب Class أو فسادها أو تعددها يحافظ على المسار الأصلي. مسار ai يبقى كما هو. لا يعد المرشح إصلاحًا لفقد Class أو لإعادة استخدام جميع هويات جلسة قديمة.

حماية نطاق NAS تعني أن جلسة على راوتر آخر لا تدمج تلقائيًا مع الأولى، حتى لو نُسخ Class ومعرّف الجلسة. تغير Class بعد مصادقة جديدة يميز الجلسة الجديدة. تشارك راوترين فعليين في جميع هويات NAS يظل بحاجة لتصحيح الهوية أو تحقق مستقل.

## الفحص

`python tests/run_accounting_identity_lab.py --run` ينشئ جولة جديدة وشبكة Docker داخلية دون منافذ منشورة، باستخدام صور محلية مثبتة. لا يستورد التطبيق ولا يصل إلى عميل أو LAB أو سجل خارجي، ولا يعيد أي مشغل مالي سابق. ينقل DDL المصدر دون seed أو dump، ويشغّل FreeRADIUS وMariaDB فعليين وUDP بإيصالات يتحقق توقيعها.

يشمل الاختبار إعادة إنتاج العيب على baseline، وتغيّر المنفذ وStart/Interim/Stop، وحفظ الهوية القديمة وعدم دمج التاريخ الملتبس، وفصل الحسابات والراوترات والجلسات، والحزم المتكررة والمتأخرة وعدادات64 بت، ورفض السعة والترخيص المنتهي أو الملغى وحاجز التجديد. يعيد تشغيل Core المملوك للمختبر للتحقق من استمرار جلسة مفتوحة وعدم تكرار استدعاء السياسة. الاختبار المكثف يستخدم هويات NAS محاكية متعددة وجلسات متزامنة؛ لا يثبت تنقلًا فعليًا بين أجهزة RouterOS.

تشغّل السعة الدوال والتريغرات الأصلية داخل fixture. حالة الترخيص مصطنعة، ومسار تجميد العقد محايد لعدم وجود عقد مدفوع. لا تعني هذه النتيجة اختبار توقيع ناشر فعلي أو بيع وتجديد وتسوية مالية كاملة. النتائج والسجلات واللقطات محفوظة في دليل monitor-reports الخاص؛ الحاويات الجديدة توقف وتحفظ، وحالات الحاويات السابقة تقارن قبل وبعد.

أضيف قبول مستقل على LAB بصورة Core الفعلية، ثم براوترَي RouterOS CHR وجهاز مشترك افتراضي. أثبت ثلاث جلساتPPP متزامنة وتعدد الراوترات وانتقال حساب وأربع نهاياتStop أصلية. مشغله خاص بالهدف والأدلة المحمية، وليس جزءًا من الأمر المحلي أعلاه ولا يسمح بإعادة جولة مغلقة. راجع النتائج للهوية الحالية وحدود العقود المدفوعة والأجهزة المادية والحمل الطويل.

## حدود النشر والتراجع

لا نشر تلقائي. يلزم بناء خاص مشتق من Core المقبول في الهدف، وحفظ الحاوية وطبقة writable والإعدادات والنسخة المشفرة الحديثة، والتحقق خارج المضيف قبل الاستبدال. لا تتضمن حزمة الهدف تغييرات مصدر غير مرتبطة كانت موجودة في checkout.

الرجوع إلى صورة لا تعرف المعرّفات الجديدة قد يقسم جلسة بدأت تحت المرشح؛ لذلك يجب اختبار تراجع متوافق يحتفظ بربط السجلات الصحيحة أو خطة انتقال محددة قبل أي اعتماد. لا تستعد DB قديمة، ولا تغلق أو تدمج سجلات العميل تلقائيًا، ولا تغيّر quota أو تراخيص لمعالجة عدم اتساق الهوية.

يضيف المرشح قراءة SQL لكل حزمة مؤهلة. يلزم قياس الأداء والفهارس في LAB، وليس استنتاج القدرة الإنتاجية من مدة الاختبار المحلي أو من حد LIMIT وحده. لا يتغير إعداد NAS أو التسجيل ضمن هذا التغيير.
