## العميل بعد تفويض إضافي

استُثني CLIENT_AS عند النشر الأول بحسب طلب المستخدم آنذاك. بعد اكتمال الدومينات، طلب المستخدم بدء تحديث `192.168.33.33` صراحةً. أثبت الفحص الجديد هوية SSH والعتاد وDocker وملكية max-radius وصورة r37 الحالية و12 طبقة Compose. لم تستخدم مشغلات أو جولات مالية قديمة.

اكتمل Web الآن على r38، بالحاوية `1ab25669ecc0`. رقم الإصدار بقي 2.7.1. التغيير صيانة مباشرة للبناء نفسه مع توقيع الصورة وقفل dispatch وعقد الإقلاع ومهلة الترخيص الطبيعية والنسخة الاحتياطية وخطة الرجوع؛ القناة الاعتيادية لا تقبل إصدارًا مساويًا، ولم تعدل قاعدة قبول الإصدارات أو تصطنع عرضًا موقعًا. بقي محرك التحديث والقناة والحارس والتسجيل كما هي. بقي ملفا web-gate.sh وnormal_launch.py ببصمتيهما، وحُفظ المرجع الجديد في أعلى طبقة Compose الفعلية، مع تطابق بقية خدمات التعريف بعد التركيب.

### خطأ مشغل التطبيق والرجوع

في المحاولة الأولى افترض مشغل الصيانة الخاص بهذه الجولة اسم خدمة `web` عند حفظ Compose، بينما اسم العميل `wisp-web`. أقلعت الصورة الجديدة ونجحت فحوصها ومقارنة بياناتها، ثم أعاد المشغل Web إلى r37 تلقائيًا عند KeyError، دون استعادة قاعدة البيانات. ثبتت عودة HTTP 200 وتطابق بيانات المبيعات والاستهلاك والـCompose قبل أي محاولة جديدة.

صُحح المشغل الخاص، واختُبر تعريف العميل المعزول بطبقاته الاثنتي عشرة: تغيير صورة خدمة wisp-web وحدها، ثم رجوع التعريف المطابق للأصل. نُفذت جولة جديدة وحيدة بعد ذلك ونجحت. هذا خطأ في مشغل الصيانة الذي جهزناه، وليس تغييرًا أو خللًا جديدًا في الصورة المنشورة أو محرك العميل. بقيت حاوية المحاولة الأولى متوقفة مع restart=no، واحتفظت الجولة بحاوية r37 للرجوع. لم يحذف شيء منها أو من الصور أو volumes أو النسخ الاحتياطية.

### قبول الخدمة والبيانات

- بقيت الحاويات الأصلية الإحدى عشرة خارج Web متطابقة، بما فيها Core وMariaDB ومحرك التحديث والحاويات المتوقفة السابقة. الإجمالي 12 ثم 14 حاوية بسبب الاحتفاظ بالمحاولة والحاوية البديلة. لم يعد تشغيل Core أو DB أو المحرك.
- طابق تخصيص FreeRADIUS المصلح لحالات حد الحساب ومنع MAC البصمة المحمية السابقة؛ لا تغيير NAS أو ترخيص أو حصص أو أرصدة.
- طابقت بصمات 40,090 بيعًا و29,680 ملخصًا و184,517 ختمًا قبل وبعد. لم توجد فواتير في جدول العميل في هذه اللقطة. بقيت المهام الست وسجلها، ولم يستأنف حذف كروت.
- بقيت هويات الجلسات الـ153 في عينة ما قبل التبديل، وتقدمت جميعها دون فقد UID أو تراجع عداد. سجلت الدقائق العشر الأخيرة 161 قبولًا طبيعيًا، منها قبول بعد التبديل.
- رصدت متابعة هذه العملية 337 عينة دون إنذار Core/DB/المحرك/الـlease ودون خطأ رصد، و223 قبولًا طبيعيًا منذ بدايتها. فشلت خمس قراءات HTTP ضمن ثلاث نوافذ أثناء التبديل والرجوع: فواصل القراءتين الناجحتين المحيطتين بها 4.87 و7.43 و7.30 ثانية. هذه حدود أخذ العينة وليست قياسًا دقيقًا لمدة انقطاع HTTP. الواجهة عادت 200؛ لا ادعاء بانعدام انقطاع لحظي للواجهة.
- متابعة العملية انتهت؛ المراقبة الدورية as لم تستأنف، ولا توجد مراقبة دائمة جديدة.
