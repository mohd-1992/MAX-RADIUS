# الاستيراد والبيانات التاريخية

## ملف الحزمة MAX-VOUCHERS-1

تُصدر `batch_export_service` ورقة Cards بأعمدة ثابتة، وتقرأها `parse_excel_file` الحالية دون تغيير الأصفار أو كلمات المرور. الحقل voucher_pin مستقل عن aliases القديمة pin/pin_code التي تعني username في الملفات العامة. وجود export_format يختار `batch_restore_service`، ولو كانت قيمته فارغة؛ لا سقوط صامت إلى استيراد كروت جديدة برصيد كامل عند تلف الإصدار. تُرفض الحقول الناقصة والأرقام السالبة/غير المنتهية وتواريخ الدورة الناقصة.

هذا المسار يحفظ تواريخ الاستخدام/الدورة/الانتهاء واللقطات والإضافات والحالة والاستهلاك الدقيق بالبايت والثانية، بغض النظر عن خيار الاستهلاك في نافذة Excel العامة. لا يُعيد تفعيل المنتهي أو الموقوف أو المستهلك للشحن، ويعيد تقييم انتهاء التاريخ/الحصة/وقت الاستخدام منذ التصدير. الحالة unused غير المجمدة تبقى خاضعة لسياسة أول استخدام. الباقة المطابقة يجب أن تكون موجودة، وملكية الاستيراد هي المختارة في مسار الاستيراد القائم.

معاملة واحدة مع SERIALIZABLE في MariaDB ترفض أي حساب/RADIUS أو محاسبة محفوظة بالاسم قبل الكتابة. لا تدمج تاريخًا محفوظًا مع مجموع الملف، ولا تمس NAS أو مبيعات أو baseline. يُكتب ملخص تاريخ مشتق فقط عند غياب التعارض، وتبدأ محاسبته بحد الدورة المصدّر؛ فشل صف واحد يرجع الحزمة كلها. حماية التكرار وقيود username/serial في القاعدة باقية.

الملف لقطة عند التصدير وليست نسخة احتياطية كاملة: لا يعيد المبيعات أو سجل الجلسات التفصيلي أو استخدامًا حدث بعد التصدير. عند بقاء محاسبة أحدث أو عدم وضوحها يلزم مسار استعادة محقق منفصل؛ لا تحاول تجاوز الرفض أو حذف التاريخ لإجبار نجاح الاستيراد. يحتوي الملف بيانات دخول حساسة ويجب حفظه خاصًا.

المصادر: services/import_service.py و database_migration_service.py و mikrotik_userman_importer.py و userman_job_service.py و import_state_service.py. الجداول والتريغرات في [DATABASE](DATABASE.md)، والسياسة التجارية في [FIRST_USE_POLICY](FIRST_USE_POLICY.md).

## السياسة الحالية

SQL/Excel/User Manager تمر عبر المخطط والسياسة نفسها: حساب بلا تاريخ استعمال ينتظر تثبيت حصة وسرعة وسعر وتكلفة الباقة عند أول قبول. الحساب التاريخي يحتفظ باللقطة المستوردة؛ جلسة أو بيع أو قبول سابق أو تاريخ استخدام/تجديد/انتهاء دليل لا يعاد تصنيفه كجديد. @max_radius_import يحمي لقطة العقد المثبت عند التحديث المستورد. لا يمكن استنتاج حصة تاريخية لم يسجلها المصدر أصلًا.

مطابقة أعمدة Excel تعتمد اسمًا أو بديلًا كاملًا، وتمنع الترويسة الملتبسة/المكررة؛ لا تبحث عن up داخلاسم uptime. تبقى وحدات الوقت والرفع والتنزيل مستقلة. اتجاه حد MikroTik رفع/تنزيل مع البيرست والحد الأدنى المعروفين؛ صفر حد كامل يحفظ معنى السرعة المفتوحة. لا تعِد تفسير العقود المستخدمة جماعيًا بتخمين الاتجاه.

المحرك يميز صفر الحصة والرصيد من NULL/غياب القيمة. الحساب المعطل في المصدر يبقى معطلًا؛ وجود باقة مفتوحة في الهدف لا يلغي حد مصدر تاريخي محفوظ. الاستيراد التفصيلي خيار مستقل للمحاسبة والتاريخ، وليس مجرد عدد حسابات مجهزة.

## User Manager والدفعات

السحب بالخلفية يعرض عدد السجلات الواصلة والبروفايلات ومعاينة محدودة؛ المصدر الكامل خاص في storage/userman-jobs، وليس داخل static أوالصور أو Git. اعتماد الراوتر في ذاكرة العامل. هوية صاحب المهمة وصلاحية الاستيراد شرط للقراءة والإلغاء.

الاستيراد يعالج 200 سجل لكل معاملة، مع إيصال وسجل قبل/بعد في المعاملة نفسها. الإلغاء يتراجع عن الدفعة الجارية ثم يعكس آثار الدفعات المحفوظة الآمنة فقط. أي محاسبة أو قبول دخول أو حجز أو بيع أو تغير عقد/اعتماد أحدث يحفظ الحساب للمراجعة. لا تعاد دفعة بعد commit مجهول؛ الإلغاء الصريح قابل للاستئناف دون إعادة الاستيراد. رقم الحزمة الفني يضم هوية الباقة وعشوائية مستقلة؛ الاسم الظاهر ومرجع المهمة مفهومان مختلفان.

قفل userman-import يتبادل الرفض مع إعادة المصنع، ولا يمنح مجرد فتح الصفحة إذن مسح أو سحب حي. بعض مسارات GET في التطبيق قد تستدعي مزامنة/تهيئة؛ لا تعتبر كل GET قراءة آمنة تلقائيًا. فحص جولة التوثيق لم يفتح مهام استيراد أو ينفذ initializer.

## إصلاح محلي لمحرك User Manager — 17 أكتوبر 2026

التاريخ يحتاج أول استعمال ودورة وانتهاء أصليًا عند محدودية الصلاحية، و`source_sessions` تغطي مجموع الدورة بدقة الثواني. تطابق الجلسة Session-ID وNAS بعد تفسير alias والمستخدم وMAC وIP وبداية ضمن ثانية، مع عدادات هدف غير متناقصة. الجلسات السابقة للدورة لا تدخل استهلاكها؛ لا يختلق baseline للجلسة العابرة. صفوف NAS الأصلية محفوظة والجزء المشترك لا يضاف مرة ثانية.

التحقق محافظ: التجميع وحده والتواريخ الناقصة والجلسات المفتوحة/العابرة أو جلسة مصدر بلا نظير هدف مثبت تُترك للمراجعة دون إنشاء حساب أو استهلاك مفترض. نهاية المصدر وحدها لا تثبت عدم وصول Start/Stop متأخر؛ لا يضاف تجميع موجب دون حد انتقال مثبت. السحب الحالي API/RSC لا يضمن التاريخ التفصيلي أو التواريخ الأصلية؛ لا يصنعها الإصلاح. عدد وأسباب الحالات المحجوزة تظهر في النتيجة، والمصدر الخاص محفوظ. الحسابات الجديدة دون استعمال تبقى ضمن سياسة أول استخدام. ليس هذا إصلاحًا تلقائيًا للحسابات القديمة.

الإلغاء الكامل/الجزئي ظاهر بالواجهة. يحفظ المتصفح مرجع المهمة غير المحسومة ويتيح استئناف الإلغاء؛ يتحقق الخادم من الملكية وقفل الاستيراد. `wisp_userman_import_batches/journal` تحفظ إيصالات وصور قبل/بعد خاصة؛ لا تعرض محتوياتها أو تدخلها Git/الصورة. عكس الأثر مقتصر على السجلات التي أنشأتها المهمة أو غيرتها، مع مقارنة صورتها الحالية؛ المحاسبة الفعلية والمالية محفوظتان. الموارد المشتركة/المعدلة تبقى للمراجعة، والمعرفات لا يعاد استخدامها، ولا تستعاد قاعدة قديمة.

الحالة: تنفيذ واختبار محليان فقط، دون نشر أو تعديل قاعدة العميل. الاختبارات: `tests/test_userman_evidence.py` و`tests/test_userman_progress.py` و`tests/userman_rootfix_mariadb.py` و`tests/userman_cancel_ui.cjs`. لا تعني اختبارات SQL نجاح بروتوكول RADIUS أو راوتر فعلي.

اختبارات الترويسات والدفعات والتراجع والتكرار واتجاه السرعات مسجلة في [TESTING](TESTING.md). نجاح fixture/HTTP أو UDP لا يثبت جلسة CHR أو بيانات الاستيراد على عميل فعلي. لا تعِد driver قديمًا؛ اقرأ journal والأثر أولًا. إصدار 4K المقاس أقدم ولا يثبت أن كل هذه الإصلاحات منشورة عليه؛ [ENVIRONMENTS](ENVIRONMENTS.md).
