# البناء والنشر والتراجع
مصادر البناء: [Dockerfile](../Dockerfile)، [Dockerfile الراديوس](../docker/freeradius/Dockerfile)، [Compose المحلي](../docker-compose.yml)، [Compose الإنتاج](../docker-compose.production.yml). أسماء الخدمات والمنافذ تختلف حسب النشرة؛ استخرجها من ملف الهدف وlabels ولا تعتمد على اسم حاوية مأخوذ من بيئة أخرى.

تجميع الوحدات الأمنية في Dockerfile يستخدم Cython ثم يحذف المصادر المحمية من runtime. عند إضافة وحدة جديدة راجع COPY وقواعد الحزمة، وليس مجرد وجودها في checkout. الوثائق والمهارات والأدوات المضيفة لا تحتاج دخول الصورة التشغيلية.

`python scripts/project_tools.py build-plan --tag review-20261011` يعرض أوامر بناء محلية فقط. قبل نشر مصرح به: راجع التغيير والاختبارات، احفظ هوية الصورة السابقة وCompose ونسخة DB إذا هناك ترحيل، ابنِ tag واضحًا، حدث الخدمة المحددة فقط، ثم تحقق من الصحة والكود/التريغر المثبت والبيانات. التراجع عن الصورة لا يعكس ترحيل البيانات تلقائيًا.

نشرة ماكس المستضافة تستخدم مشروع Compose خاصًا وحاويات `max_radius_max_web/core/db`. هذه أسماء لقطة بيئة، لا ثوابت لعميل جديد. اخر صورة متحقق منها في [CURRENT_STATE](CURRENT_STATE.md).

Docker metadata proxy لا يسمح exec/stop/start العامة. مسار إعادة المصنع المستضاف يحتاج controller المقيّد والمطابقة مع journal ومشروع المستأجر؛ راجع [دليل controller](../deploy/hosted-max/README.md). لا تحل 403 بتركيب socket كامل في الويب أو توسيع التحكم لكل الدومينات.

إعادة المصنع والاستيراد والاستعادة عمليات بيانات ذات نطاق مستقل. تنسيقها مع دورة الصيانة وإلغاؤها وتوقف الراديوس جزء من العملية؛ لا تشغّلها على قاعدة العملاء ضمن اختبار واجهة عابر.
