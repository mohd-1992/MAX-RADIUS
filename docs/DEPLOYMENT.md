## قبول خادم Linux الأصلي في مختبر اللوحة — 19 أكتوبر 2026

لم يُعدّل كود MAX في هذه الجولة؛ طابقت بصمات خدمات L2TP والمحدّث وملفات docker/l2tp المصدر المجمد. اختُبر الخادم الأصلي في Linux 6.6.142 داخل QEMU وحاوية معزولة لتجاوز قيد نواة WSL دون تغييرها. نجح PPP مع RouterOS والربط من اللوحة وNAS API و105/105 حزم ناجحة، وصف SQL واحد مع Interim عند 900 ثانية وStop فعلي عند 1052 ثانية؛ الإدخال 92614 والإخراج 77370 بايت وactive=0. نجح التعافي الصريح والتحديث الأصلي والتراجع ورفض مرشح تالف؛ التوقيع والترخيص والـlease بعد الرجوع صحيحة.

التقرير والدليل في المشروع الشقيق `max_saas_panel_v2_local/reports/LINUX_L2TP_ACCEPTANCE_20261019.md` وJSON المجاور، ووصفة `docs/LINUX_L2TP_LAB.md` فيه. يعلن التقرير ترجمة QEMU وNAS API ومسارات المختبر وإعادة RADIUS الصريحة، وإيصال تراجع تحقق بعد مهلة الرد دون إعادة تنفيذه. لا تعيد أي مرحلة أو driver أو restore من هذه الجولة؛ صفها المالي مغلق فعليًا. توقفت جميع الحاويات الـ39 الجديدة، وحالات 344 حاوية سابقة لم تتغير. لا نشر أو عميل أو مفاتيح إنتاجية.

المتبقي: HTTPS enrollment/heartbeat وRegistry، وشبكة نشر ممثلة دون الترجمة، وتقوية افتراضات عناوين/اعتمادات Linux وإبطال اعتماد قديم، وإعادة تشغيل مضيف كامل والحمل الطويل. هذه نتيجة مختبر مستقلة ولا تعتمد أي بيئة LAB أو عميل تاريخية أخرى.

التحديث من اللوحة في مرشح2.6.3 موثق في [SYSTEM_UPDATES](SYSTEM_UPDATES.md): مصدر HTTPS، صورة Web مثبتة، نسخ إلزامي، helper مستقل وحالة محفوظة؛ لا Compose عام أو تحديث خدمات أخرى. المرشح على LAB فقط ولم ينشر Git/Registry. لا تعتمد على ملف Compose أرشيفي لإعادة إنشاء معاينة أحدث؛ طابق image ID وملف override الحالي المسجل في جولة النشر. لا تخلط image ID المحلي مع digest Registry المطلوب لبيان الإصدار بعد الرفع المصرح به.

مرجع التشغيل المقاس الوحيد [ENVIRONMENTS](ENVIRONMENTS.md)، والتفاصيل الإدارية في المرجع الخاص؛ هذه الوثيقة قواعد تحديث وليست قائمة بيئات أخرى. جولة التوثيق لم تبن أو تنشر صورة.

لا تعتمد على اسم latest وحده لإثبات الإصدار. راجع image digest وMounts وبصمات ملفات التشغيل؛ bind mount لملف أو مجلد من core/services/web/database يتجاوز محتوى الصورة. لا تضف hotfix إلى حاوية عميل خارج المصدر وحزمة الإصدار المعتمدة. الاستثناء المحلي للتطوير يوثق صراحة ولا ينقل إلى الإنتاج. نسخة الرجوع يجب أن تحفظ أي ملفات مربوطة موجودة، وليس وسم الصورة فقط. انظر نشرة توحيد4K في CURRENT_STATE.
مصادر البناء: [Dockerfile](../Dockerfile)، [Dockerfile الراديوس](../docker/freeradius/Dockerfile)، [Compose المحلي](../docker-compose.yml)، [Compose الإنتاج](../docker-compose.production.yml). أسماء الخدمات والمنافذ تختلف حسب النشرة؛ استخرجها من ملف الهدف وlabels ولا تعتمد على اسم حاوية مأخوذ من بيئة أخرى.

المثبتان `install.sh` و`scripts/install.sh` يقرآن `release.json`، ويتحققان من SHA256 لحزمة التشغيل ذات قائمة الملفات الثابتة (خمسة للتشغيل، وخمسة لأدوات المضيف الاختيارية فيR13)، ويكتبان `runtime-release.env` بمعرفات صور ثابتة قبل سحب صور Compose الإنتاج. تحديث `latest` وحده لا يغير الإصدار الذي يثبته البيان. تحديث Git وحده لا يحدّث الصور. عند التحديث اليدوي استخدم `pull` ثم `up -d` مع نفس مشروع وملفات Compose الفعلية. Autoheal تضبط `pull_policy: always` في ملفّي Compose، فتفحص الصورة عند تشغيل خدمتها حتى لو كانت نسخة محلية موجودة؛ يتطلب ذلك وصول Registry، ولا يعني تحديثًا دوريًا للحاوية القائمة. قارن digest الحاوية المشغلة بعد التحديث، لا اسم latest فقط. المسار القديم `deploy/ubuntu/install.sh` يبني محليًا وله متطلبات تغليف مستقلة.

تجميع الوحدات الأمنية في Dockerfile يستخدم Cython ثم يحذف المصادر المحمية من runtime. عند إضافة وحدة جديدة راجع COPY وقواعد الحزمة، وليس مجرد وجودها في checkout. الوثائق والمهارات والأدوات المضيفة لا تحتاج دخول الصورة التشغيلية.

`python scripts/project_tools.py build-plan --tag review-20261011` يعرض أوامر بناء محلية فقط. قبل نشر مصرح به: راجع التغيير والاختبارات، احفظ هوية الصورة السابقة وCompose ونسخة DB إذا هناك ترحيل، ابنِ tag واضحًا، حدث الخدمة المحددة فقط، ثم تحقق من الصحة والكود/التريغر المثبت والبيانات. التراجع عن الصورة لا يعكس ترحيل البيانات تلقائيًا.

نشرة ماكس المستضافة تستخدم مشروع Compose خاصًا وحاويات `max_radius_max_web/core/db`. هذه أسماء لقطة بيئة، لا ثوابت لعميل جديد. اخر صورة متحقق منها في [CURRENT_STATE](CURRENT_STATE.md).

Docker metadata proxy لا يسمح exec/stop/start العامة. مسار إعادة المصنع المستضاف يحتاج controller المقيّد والمطابقة مع journal ومشروع المستأجر؛ راجع [دليل controller](../deploy/hosted-max/README.md). لا تحل 403 بتركيب socket كامل في الويب أو توسيع التحكم لكل الدومينات.

المتحكم العام الحالي قد يسمح start/stop لراديوس المستأجر المسجل فقط ضمنjournal إعادة المصنع، ولا يسمح بذلك كـDocker APIعام. توجد نسخة خاصة تاريخية لماكس؛ اختيارالمشغلالفعليمنsystemd لا مناسمملففيالمستودع.

قبل أيoffline bundle راجع [SECURITY_REVIEW](SECURITY_REVIEW.md): سكربتrsync القديم لا يطبقGit/Dockerignore، لذلك قد ينسخ بيانات خاصة حتى لو لم تدخل صورةWeb. لا تعالج هذا الخطر بتدوير مفاتيح أو تعديل سكربت تشغيل ضمن مهمة توثيق.

إعادة المصنع والاستيراد والاستعادة عمليات بيانات ذات نطاق مستقل. تنسيقها مع دورة الصيانة وإلغاؤها وتوقف الراديوس جزء من العملية؛ لا تشغّلها على قاعدة العملاء ضمن اختبار واجهة عابر.
