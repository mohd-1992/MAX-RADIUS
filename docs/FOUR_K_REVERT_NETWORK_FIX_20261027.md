# رجوع 4k إلى 2.6.5 وإصلاح شبكة المتحكم — 27 أكتوبر 2026

## التشغيل الحالي

بطلب الإنسان سُحبت إتاحات 2.6.6 و2.6.7 و2.6.8 من هوية 4k فقط عبر API، مع حفظ تاريخها. كانت المهمة `733e40434a1e457392fe29c5f1758200` متوقفة بحالة `recovery_required` عند 95% بعد نجاح تبديل Web وفشل تسليم المتحكم؛ لم يكن هناك عامل تحديث جارٍ يلزم قتله.

أثبت الفحص عدم تنفيذ ترحيل 2.6.8 وغياب جداول MAC الجديدة. أُعيدت حاوية Web الأصلية `489af1dd9ba0` بإصدار 2.6.5 إلى اسمها وشبكتها، وحُفظت حاوية 2.6.7 الملغاة متوقفة. أُعيد ربط المتحكم الأصلي `859c7f8638c4` بشبكة `bridge` بعنوان ديناميكي وشُغّل بصورته السابقة `c61766679bbc`؛ بقيت خدمة المضيف القديمة معطلة.

إيصال القبول عند 26 أكتوبر 21:33:11 UTC يثبت سلامة Web والمتحكم والختم والترخيص والـlease، واستجابة صفحة الدخول العامة HTTPS 200. فحص القناة يعيد `has_update=false`. المهمة أصبحت `rolled_back` بإيصال تدخل الإنسان، مع حفظ حالة الفشل والخطة والسجل الأصليين. حُفظت 282 عينة محاسبة دون فقد أو انخفاض عدادات، وثبتت هوية وصورة ووقت بدء Core وDB وبقية الخدمات المحمية. لم يحدث DBrestore أو DDL أو تعديل NAS أو CoA أو عملية مالية أو مصادقة اختبارية على الخدمة الحية. هذه عينة حفظ بيانات وليست ضمانًا لكل معاملة أو إثبات مرور طلب راوتر جديد.

## السبب المؤكد والإصلاح

كانت `endpoints_for` تحوّل عنوان شبكة Docker الافتراضية `bridge` الديناميكي إلى عنوان IPAM ثابت. رفض Docker إنشاء المتحكم الجديد، ثم رفض إعادة ربط القديم بالإعداد نفسه، بالخطأ: `user-specified IP address is supported on user-defined networks only`. الخلل في المحرك وليس المتصفح. اختبارات السلسلة السابقة استخدمت شبكة `none` للمتحكم، ولذلك لم تكشف الحالة.

- ترسل شبكة `bridge` الافتراضية إعداد endpoint فارغًا عند الإنشاء والرجوع، دون عنوان ثابت أو aliases.
- تحفظ الشبكات المخصصة عنوانها والأسماء المطلوبة.
- لا يرسل `host` و`none` إعداد NetworkingConfig أو طلب فصل غير مدعوم.
- تُرفض مساحة الشبكة المشتركة `container:` والأوضاع غير المدعومة قبل إيقاف الخدمة. يفحص `freeze` إعداد شبكة وتخزين المتحكم قبل تبديل Web.
- تتحقق مراحل الترحيل من إعدادات التشغيل والرجوع قبل الإيقاف، دون تغيير SQL الترحيل.

الملفات: `services/system_update_runtime.py` و`system_update_handoff.py` و`system_update_executor.py` و`system_update_migrations.py`. أضيفت حالات في `tests/test_update_networks.py` و`tests/test_update_handoff.py`. لم يتغير كود اللوحة المشترك أو مرجع الثقة على الخادم.

## الفحوص والبناء المحلي

شُغّلت ست مجموعات محددة الصلة، كل واحدة في عملية Linux معزولة: 84 حالة، منها 83 ناجحة وواحدة متجاوزة. التشغيل الأول في مفسر واحد كشف تعارض هوية فئة UpdateError بسبب إعادة تحميل الوحدات في الاختبارات القديمة؛ لم يُحسب نجاحًا، واعتمد التشغيل المعزول.

بُنيت أربع صور محلية مختومة: مرحلتا المحرك، وصورة الميزات، وصورة الرجوع المتوافق. بقيت جميع ملفات التشغيل الأخرى مطابقة للصورة الأساس دون حذف، ولم تتغير صورة Core. استُكملت تبعية `system_update_sequence` في صورتي الميزات والرجوع بعد أن كشف اختبار التغليف غيابها؛ الصور النهائية الأربع اجتازت 26 فحصًا لكل صورة على الوحدات المجمعة نفسها. [بيان الصور المحلية](../releases/local-network-fix-20261027-r1.json).

نجحت تسع حالات Docker فعلية على المحرك المجمع: نجاح وفشل متعمد بعد فحص المنفذ والتوقيع لكل من `bridge` وشبكة مخصصة و`none` و`host`، وحالة فشل إضافية على `bridge` بإعداد Init=false كما في 4k. تحقق الرجوع الفعلي للمتحكم ومنفذه، وإعادة التشغيل وحفظ السجل. هذه اختبارات للمتحكم معزولة دون SQL أو NAS.

نجحت سلسلة كاملة جديدة على شبكة bridge الافتراضية في نموذج دومين ونموذج تثبيت محلي، ونجح الرجوع المتوافق بعد فشل متعمد في مرحلة الميزات. تحققت مصادقة FreeRADIUS وحزم Start/Interim/Stop وعدادات 64 بت وحفظ الرصيد وسياسة MAC بعد النجاح والرجوع، دون استعادة DB أو إعادة تشغيلها. تحققت التوقيعات والتتابع وحفظ الإيصال بعد إعادة تشغيل المتحكم. بقيت خدمات الجهاز الأصلية ثابتة. استُخدمت بيانات مصطنعة؛ ترخيص الناشر ونقل Registry محاكيان، فلا تمثل النتيجة قبول NAS حيًا أو اختبار تنزيل من Docker Hub.

لا توجد صورة إصلاح منشورة أو إتاحة جديدة أو محاولة تثبيت جديدة على 4k أو دومين آخر. لم تُستأنف مراقبات PAUSED، ولم يُنشأ مراقب دوري لـ4k قبل طلب إيقاف المحاولة.

## المحاولة التالية والحدود

يحفظ ناشر الإصدارات تاريخ الأرقام المنشورة والمسحوبة، ويرفض إعادة نشر رقم سابق للجمهور نفسه. تحتاج المحاولة القادمة أرقامًا أحدث ومسودات جديدة؛ لا تعديل للوسوم القديمة ولا تجاوز للسجل. لم تحدد أرقامها ولم تنشر في هذه الجولة. ما زال حاجز بصمة `release_center.py` في لوحة الإدارة القديمة خارج هذا الإصلاح؛ المسار المقبول سابقًا هو صفحة التحديث داخل النظام.
