# أرشفة وتلخيص التاريخ — تجربة محلية 4 نوفمبر 2026

التعديل في مصدر 2.7.0، محلي فقط. أساس المقارنة Web1508c922f512 المجمع، والمرشح المصدر الحالي مركب للقراءة داخل المختبر على الأساس نفسه. لم تبن صورة مرشحة نهائية ولم يحدث نشر أو وصول لأي عميل أو دومين أو راوتر أو جهة ترخيص. هذا قبول المصدر، ولا يعد قبول صورة مجمعة جديدة.

## ما تغير

1. عداد الأرشفة يتبع المدة المختارة30/90/180/365 مع منع رد متأخر من استبدال الاختيار الجديد. تعذر القراءة يظهر «—». عداد التلخيص عدد كروت مرشحة؛ تثبت الأهلية داخل معاملة الحساب.
2. أرشفة صفحة الصيانة أصبحت مهمة خلفية في سجل الصيانة القائم، مع نتيجة دائمة ومتابعة وإلغاء بعد إعادة تحميل الصفحة. الإلغاء ينهي الحساب/الدفعة الجارية بأمان. تختفي بطاقة التقدم عند النهاية مع إشعار مرة واحدة. ضياع الرد أو انقطاع العامل لا يعيد تنفيذ المهمة تلقائيًا. المستدعون القدامى والأتمتة بقيت عقودهم متوافقة؛ لم تحول كل واجهات الأرشفة إلى خلفية بهذه الجولة.
3. وضع اختياري يلخص جلسات الكروت المنتهية بواسطة المحرك القائم `purge_details(history_only=True)`، دون إنشاء محرك أو جدول آخر. يبقي الكرت وبيانات دخوله والحصة والمال وMAC وإيصالات العمليات وبصمات UID. تفاصيل الجلسات الملخصة لا تبقى صفوفًا منفردة. الافتراضي يظل حفظ التفاصيل في الأرشيف.

لا تحويل إلى `COMPRESSED`، ولا تعديل RAM أو Compose أو DB، ولا تحسين جداول تلقائي. عقد الملخص موجود أصلًا في Web/Core2.7.0؛ التعديل الحالي يخص Web ولا يضيف كود Core أو صيغة ملخص جديدة. لا يعني ذلك توافقًا مع Core أقدم لا يعرف هذا العقد.

## نطاق التلخيص الآمن

يقبل تاريخ `radacct` الفيزيائي القديم المحسوم للكرت المنتهي فقط، بعمر المدة المختارة وبحد أدنى48ساعة. يؤجل الكرت كاملًا عند جلسة مفتوحة/حديثة/غير مؤكدة، ملكية أو UID ملتبس، جلسة تعبر حد دورة، خط أساس تجديد، حجز/تجديد قائم، أو أكثر من5000تفصيل. زيادة عدادات متأخرة فوق بصمة محفوظة تبقى للمراجعة بدل إسقاطها أو تكرارها.

وجود تاريخ مستورد/مؤرشف أو نسخة UID في مخزن آخر يؤجل الكرت. السبب مثبت: الحصة الحية تعتمد المصدر الفيزيائي والملخص، بينما تقارير التاريخ تقرأ مخازن إضافية. إدخال تاريخ مستورد في ملخص الحصة الحية دون توحيد عقد قراءته قد يغير الرصيد. لم نتجاوز هذه الحماية للحصول على حجم أصغر.

## التحقق وحدوده

نجح79اختبارًا معزولًا على Python3.11/Linux، و31حالة تكامل محلية، وثلاث عمليات نسخ واستعادة فعلية مع المطابقة، وفحص146ملفPython و80قالبJinja، واختباراNodeللأرشفة ولتوافق إخفاء تقدم الحذف.

تغطية التكامل تشمل اختلاف المدد؛ rollback بعد النسخ وقبل الحذف وبعد كتابة الملخص؛ عدم الازدواج؛ عاملًا خلفيًا فعليًا؛ الإلغاء قبل التشغيل وبين الدفعات والحسابات؛ فصل أنواع المهام؛ stale/interrupted دون replay؛ RBAC وCSRF وميزة الترخيص و503 عند تعذر الخدمة. تشمل حماية المفتوح والحديث وغير المؤكد وخط الأساس والحجز والتجديد والتاريخ المستورد وحد5001تفصيل وعبور الدورة، وغياب last_renewed مع first_used/created، وUID متأخر مطابق ودلتا موجبة ومالك بصمة آخر.

المطابقة على اللقطة الكبيرة تشمل جميع الكروت والمشتركين،3جداول اعتماد،11مجموعة مالية ومرجعية، الحصص لكل الكروت، قارئ الحصة الفعلي لعينة48كرتًا، وإجماليات الشبكة لكل التاريخ بعد الصيانة. بعد الاستعادة تطابق الكروت والحصص والاعتماد والمال؛ تفاصيل التقارير القديمة قد تختزل وفق سياسة النسخ القائمة، ولا تدعي التجربة الحفاظ على كل تفصيل مستبعد.

اختبارات Node تشغل handlers الواجهة الفعلية: سباق المدة، المجهول، الإلغاء، الحالات النهائية بعد reload، الإشعار مرة واحدة، وعدم إعادة POST المجهول. ليست معاينة متصفح بصرية. فشل اختبار أولًا على Python3.14/Windows بسبب غياب tzdata؛ نجح على Python3.11/Linux دون تغيير التطبيق أو تثبيت شيء على الجهاز. صحح مشغّل التكامل توقعًا اصطناعيًا: تطابق Stop وحد الدورة ليس عبورًا له؛ اختبر العبور الحقيقي بعد وضع الحد بين Start وStop. لم يتطلب ذلك تغيير التطبيق، ولم تعد أول حالتي اختبار مقبولتين.

الترخيص محاكى داخل المختبر. لا جهة إصدار حقيقية أو NAS فعلي أو ضغط إنتاج متزامن أو انقطاع كهرباء فعلي. قبل النشر يلزم بناء/توقيع صورة Web النهائية وفحص الوحدات المجمعة والقالب المضمن. لم يطلب المستخدم نشرًا بهذه الجولة.
