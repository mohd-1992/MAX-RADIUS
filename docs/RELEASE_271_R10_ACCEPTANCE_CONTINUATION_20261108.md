## الإصلاحات الإضافية المقبولة

- **التحكم بالخدمات، r8:** كان الجرد يختار اسم Core عامًا من مشروع آخر. لم يرسل أمر إليها. صار الاختيار والأمر بمعرف Docker الكامل والمشروع الفعلي، مع رفض الغياب والالتباس دون بدائل CLI/systemd عامة. نجحت 13 حالة مصدرية و10 حالات HTTP فعلية للإيقاف والبدء وإعادة التشغيل والسجلات والرفض. عادت Web المعزولة تلقائيًا بعد إعادة تشغيلها في 12.653ث، بنفس الهوية والصورة ودون تغيير Core وDB والبيانات والحاوية الخارجية.
- **NAS والأنفاق، r9:** أزيل إعادة تشغيل Core بالاسم العام، والتنفيذ غير المقيد الذي يتجاهل ExitCode. فصل PPP يستهدف الطرف والواجهة وpppd المطابقين فقط، يتحقق من ثبات الهوية، يرسل TERM ثم يؤكد الاختفاء؛ لا حذف SQL إذا لم يتأكد الفصل. المزامنة تستبدل ملفات الاعتمادات الفعالة بصلاحيات0600، وتزيل المحذوف بدل تراكمه، وتحفظ الاقتباس والشرطة المائلة كبيانات. تطابق الحذف بـIP بدل اسم العرض. نجحت10حالات مصدرية وخمس حالات فعلية مع جلستيPPP: فصل واحدة وبقاء الأخرى، حذف اعتماد الهدف فقط، وقبول NAS مع التحكم في Core الخاصة بالمشروع.
- **الملف الشخصي، r10:** غياب حقل كلمة المرور الحالية كان يتجاوز التحقق عند تغييرها. أصبح مطلوبًا لكل الأدوار في هذا المسار الذاتي، مع بقاء حفظ البيانات الشخصية دون تغيير كلمة المرور. أربع حالات مصدرية وثلاث حالات HTTP/MariaDB مترجمة ناجحة؛ كلمة المرور الجديدة تدخل والقديمة ترفض، والمحفظة ثابتة.

لا تغيير لصورة Core أو DB أو مخططهما في هذه الإصلاحات. اختبار الأنفاق استعمل PPP حقيقيًا عبر PPPoE داخل Linux؛ ليس قبولًا لبروتوكولL2TP أو NAT أو جسر المضيف المشترك. فشل إعداد TTY الأول لقيود المختبر، ولم تُحمّل وحدات نواة المضيف أو تغير إعداداته.
