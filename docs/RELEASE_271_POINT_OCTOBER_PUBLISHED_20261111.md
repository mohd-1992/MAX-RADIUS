# نشر إصلاح التصنيف ورسم أكتوبر ضمن 2.7.1 / r34 — 11 نوفمبر 2026

بطلب المستخدم أُلحقت الإصلاحات الأخيرة بالإصدار المرفوع، على **وسم 2.7.1 نفسه**، مع تحديث مصدر المستودع وبيان المثبت. الصورة هي نفسها المختبرة والمطبقة مسبقًا على max1.max-r.cc؛ لم تعد بناؤها أو تعدّل بياناتها أثناء النشر.

## ما يتضمنه التحديث

- تصحيح انقسام هوية Hotspot إلى مجموعة قديمة غير مصنفة ومجموعة جديدة، مع حفظ كل مساهمة استهلاك مرة واحدة، ومنع الدمج عند تعارض البروتوكول أو NAS أو المالك. تصحيح النوع فقط لا ينشئ قراءة أو حركة سيرفر جديدة.
- حذف عبارات وشارات «القراءة جزئية» وما شابهها من المبيعات والاستهلاك ولوحة التحكم والتصدير، وفق طلب المستخدم. تبقى البيانات غير المتاحة وحقول التغطية الداخلية محفوظة، وسجل البيع كما هو.
- عودة رسم المبيعات في لوحة التحكم إلى المبالغ الأصلية المسجلة. فاتورة أكتوبر القديمة بلا تكلفة محفوظة كانت تجعل نتيجة الشهر فارغة رغم وجود المبيعات. تكلفة المشتركين تبقى مقياسًا مستقلًا في تقريرها؛ لا تسعير جديد للتاريخ ولا تغيير للمبالغ أو التواريخ أو حصة الاستهلاك.
- جميع [إصلاحات r33 السابقة](RELEASE_271_REPORTS_PUBLISHED_20261111.md) محفوظة، ومنها الأتمتة والسجل والتقدم وقراءة CPU، مع بقاء وصف CPU المرفوض وإشعارات إكمال المهام محذوفة.

[التفصيل والقبول على الدومين](MAX1_R_271_POINT_AND_OCTOBER_R34_20261111.md) يميز تصحيح هوية العرض من إثبات بروتوكول كل حزمة تاريخية. لا إسناد للفترات مجهولة السيرفر بالتخمين، ولا إعادة كتابة لـradacct أو عدادات الحصة أو المبيعات.
