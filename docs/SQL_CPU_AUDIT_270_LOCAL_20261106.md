## طريقة القياس

استخراج SQL والدوال المطلوبة من AST للمصدر المطابق، دون استيراد التطبيق أو تشغيل عمليات مالية/انتهاء/CoA. للمقارنات3 أو5 تكرارات متبادلة A/B، على البيانات والفهارس والمحرك نفسيهما، وبلا حمل آخر في مختبر القياس المعتمد. الأرقام التالية وسيط زمن SQL مع جلب النتيجة؛ ليست أزمنة متصفح أو نسبة انخفاض CPU للسيرفر كله.

قيس وقت CPU الفعلي لعملية mariadbd من `/proc/1/stat`، مستقلًا عن CPU Python، بتشارك مساحة PID المحلية فقط. دقة هذا العداد10ms؛ نسب العينات السريعة جدًا أقل موثوقية. جُمعت قراءة الصفوف وعمليات الفرز والجداول المؤقتة من عدادات الجلسة. فُعّلت performance_schema في **قاعدة المختبر فقط**، وليس في العميل. تستهلك بعض الاستعلامات محل الاختبار نواة واحدة؛ لم تُفسر100% حاوية على أنها100% من المضيف.

المطابقة ببصمات النتائج بعد توحيد التمثيل العددي المتكافئ لـSUM/COUNT، مع حفظ NULL والتواريخ وترتيب التصدير. لا قوائم حسابات أو SQL dump أو أسرار في التقرير. قياسات quota الأولية التي تزامنت جزئيًا مع اختبارين قصيرين ليست المرجع؛ المرجع النهائي هو `quota_branches-RESULT.private.json` المستقل.

### 1. حساب الحصص بالدفعات

المسار `services/quota_service.py:get_accounting_totals_batch`. ربط الدفعة بـ`radacct_quota_owned` ثم LOWER والتجميع تسبب في قراءة نحو1.04مليون عملية قراءة مفاتيح/صفوف في عينة400حساب. البديل يقيّد **فرعي** المصدر بالحسابات المطلوبة قبل UNION مع إبقاء حساب الحصص والبدايات والتسويات كما هي؛ انخفض المؤشر إلى38,192عملية. عينة حساب واحد1193.80→1.08ms، و50حسابًا2590.04→12.19ms.

الهدف تعديل Web فقط. لا تغيير في FreeRADIUS أو الحدود أو baselines/seals أو ملكية الحساب، ولا صورة DB أو فهرس جديد مقترح لهذا التصحيح.

### 2. تاريخ الجلسات وتصديره
