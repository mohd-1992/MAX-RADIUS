## Channel and execution

`services/system_update_channel.py` implements the actual control v1 contract:
Ed25519 manifest and five-minute offer verification, reader/version/manifest
binding, domain/local/public audience checks, HTTPS without credential redirects,
minimum version and immutable allowlisted Web/Core image references. The original
control trust was verified through the protected administrative route against the
accepted private-key hash; only its public key ships. No trust is downloaded or
adopted automatically. No control announcement or installation identity is created
by building or publishing this image.

The Web routes use `system_update_control` through an installation-owned Unix
socket. Superadmin and CSRF are mandatory for apply. Version, release identity and
manifest digest must still match a fresh channel check. No arbitrary image,
program, project, migration SQL or Docker request is accepted from Web.

The controller source is `deploy/hosted-max/update_controller.py`, packaged as the
signed compiled `services.system_update_host` module. Host-only configuration and
journals are mounted separately from tenant storage. A helper from the current
trusted Web image survives Web replacement. Preparation includes a verified engine
backup without Telegram, image pulls/digest checks, stable service ownership and a
fresh availability check after preparation. Interrupted preparation is not replayed.

Execution switches only the enrolled Web/Core, retains old containers and writable
layers, verifies runtime signature, version, publisher key, license/lease, Core UDP
listeners and up to 300 frozen accounting rows/UIDs/counters. The latest DB remains
in place. Both success and rollback persist the corresponding Compose definition;
an external Compose edit produces recovery_required instead of overwriting it.
Rollback repeats runtime and accounting verification. Uncertain dispatch stays
claimed; a previously attempted release is not automatically attempted again.

The initial consumer advertises `web,core,signed_audience`. It deliberately does
not advertise `migration`: the panel's free-text migration/rollback fields are not
an executable, reviewed data migration. Explicit-migration releases remain hidden
or rejected until a separately tested migration contract is implemented. This
release does not change schema, financial rules, licensing rules, NAS or tunnels.

## Provisioning and existing installations

The signed compiled `services.system_update_provision.provision` is an offline
creation hook. Its source is `deploy/hosted-max/provision_update_controller.py`.
Run it after pinning the new deployment's images and before first Compose startup.
It adds one controller service and a dedicated read-only socket mount to Web;
root state is outside tenant storage. Hosted roles are web/radius_core/db; the
standalone Linux profile is wisp-web/freeradius/mariadb. Standalone definitions must
have their image variables resolved to approved Registry digests first.

Without a protected enrollment record the hook configures public releases only.
Domain/local targeting additionally needs the existing control target registration
and its separately delivered reader credential. Credentials are never baked into
the image. Image upload alone does not install this hook into the old panel, create
a controller service, enroll an identity or reconfigure an existing installation.
An unconfigured socket is reported as unavailable, not "up to date".

The old panel's live creation image config must be checked before creating the
requested domain; latest alone is not evidence of what it will select. No domain
is created during this release task. Current installations and AS monitoring are
outside the release execution scope. The old public release.json remains separate
from the control channel and is not rewritten merely to move Docker latest.

compiled candidate. Docker lifecycle acceptance uses fresh internal networks and
MariaDB databases with synthetic 64-bit counters; application/license probes are
explicitly injected for the lifecycle cases. It checks Web/Core switching,
candidate failure/verified rollback, lost create reply and repeat no-op. This is
not fresh licensed RADIUS/NAS acceptance or a production domain installation.
