## إضافة معتمدة للخطة: تعديل هوية المتصل مع FastTrack

أضيفت بطلب المستخدم في7نوفمبر2026. الحالة **مخطط، غير منفذ وغير مختبر بعد**. [الدليل والمقارنة](IDENTITY_FIX_LINEAGE_READONLY_20261107.md) يثبتان أن إصلاح التاريخ السابق محفوظ، وأن رفض FastTrack قيد قديم مفتوح، وليس إصلاحًا مفقودًا من الصورة.

الهدف: تمكين تعديل نوع الخدمة واسم المستخدم وIP الثابت للمشترك المتصل، ومسارات هوية الكرت المشتركة، دون اشتراط تجميد مرور تعوقه FastTrack. قيد MAC القديم يبقى خاضعًا لسياسة القائمة المخصصة؛ لا تجاوز لها. لا تغيير شكل الواجهة؛ يعالج الكود أيضًا إرسال نوع خدمة قديم مثلbroadband دون تحويل ضمني إلىHotspot عند حفظ حقل آخر، مع بقاء التغيير الصريح خاضعًا للتحقق.

الاتجاه الفني المرشح: حاجز دخول وقفل للحساب، جرد الجلسات وأجيالها، فصل الجلسات المطابقة فقط ثم انتظارAccounting-Stop حقيقي وعداداته قبل حفظ الهوية. ACK أو اختفاء الجلسة وحده لا يثبت نهائية المحاسبة. عند تأخرStop أو تغير الجيل أو تعذر إثبات الإغلاق، يرفض الحفظ بأمان دون اختلاقStop أوseal أو تغيير العقد والمال؛ قد تكون الجلسة انفصلت بالفعل، ويجب تمييز ذلك عن نجاح حفظ التعديل. لا يعطل FastTrack عمومًا ولا يغير Core/DB/NAS. التفاصيل النهائية تحدد بعد مراجعة وتنفيذ محليين.

شروط القبول قبل اعتماد الصورة:

- متصل وغيرمتصل، Hotspot وPPPoE، مع FastTrack وبدونه؛ تغيير النوع والاسم وIP والمسارات المشتركة، وعدم تراجع إصلاح التاريخ القديم.
- جلسة واحدة ومتعددة وعلى أكثر منNAS، وتبدل الجيل أو دخول متزامن، وتعديلان متزامنان، وإعادة الطلب وضياع الرد وإعادة تشغيل العامل.
- Stop فعلي متأخر/مكرر، ACK دونStop، فشلAPI/CoA جزئي أو مهلة؛ لا عدادات مختلقة أو نقصان استهلاك، ولا حفظ هوية قبل تحقق التسوية.
- ثبات الرصيد والحصة والدورة والفواتير والمبيعات والتاريخ والملكية والترخيص، واستمرار قواعد المصادقة والمحاسبة؛ تحقق RADIUS محلي فعلي بجانب اختبارات المحاكاة مع إعلان حدود NAS.
- حفظ النوع القديم بلا تغيير ضمني عند تعديل الاسم الشخصي/الهاتف/الملاحظات/كلمة المرور، وتحقق طلب التغيير الصريح وصلاحياته وCSRF والإيصال.
- عدم إدخال مسار الفصل الجديد إلى التجديد/الشراء المالي أو تغيير قواعده دون حاجة مثبتة واختبارات منفصلة؛ عدم إضعاف قوائمMAC أو فصل حساب/جلسة أخرى.
- إعادة بناء Web بعد الإصلاح واختبار الصورة النهائية نفسها وتوقيعها وتشغيلها، وإكمال الفحوص الخمس والتكامل والتوقيت/الربط/الرجوع المتبقية. لا اعتماد بأرقام اختبارات المصدر وحدها.

إضافة البند للخطة لا تستأنف العمل الموقوف؛ لا تنفيذ أو نشر في هذه الخطوة.

### المتطلبات المشتركة وشروط القبول

- حفظ الجداول اليومية متعددة الأوقات والفترات والأسبوعية والشهرية والمرة الواحدة، البداية والنهاية وحد التشغيل والمنطقة الزمنية؛ الموعد القادم محسوب خادميًا، مع سياسة صريحة للمواعيد الفائتة واليوم غير الموجود بالشهر.
- هوية فريدة لكل موعد ومنع الالتقاط المزدوج بين العمال، وقفل للمهمة وتنسيق أقفال الحذف/التلخيص/التحسين/النسخ/الاستعادة. حماية التزامن لا تعتمد على ذاكرة عملية Web وحدها.
- حالات queued/running/success/partial/failed/cancelled/skipped، تقدم فعلي، إلغاء آمن حسب نوع المهمة، وسجل محفوظ بعد حذف تعريف المهمة. استعادة حالة الانقطاع دون إعادة عملية غير مؤكدة أو خصم/إرسال مكرر.
- ترخيص وصلاحيات وملكية وCSRF وتحقق معلمات في الخادم؛ لا تنفيذ أو إرسال تلجرام من المتصفح، ولا تسريب أسرار أو تفاصيل حسابات في السجل العام. إرسال التقارير مقيد بنطاق القناة وصلاحية المستلم، وليس بمجرّد وجود إعداد قناة.
- استعمال إشعارات النظام الأصلية؛ النجاح بعد النتيجة النهائية فقط، وفصل الفشل الجزئي/الإلغاء/تأجيل ضغط الموارد عن النجاح. تنبيه المساحة في لوحة التحكم؛ التقرير قابل للعرض من سجل التنفيذ مع حالة تلجرام مستقلة.
- اختبارات محلية للوقت وحد التشغيل والمواعيد الفائتة والتوازي وإعادة الطلب والانقطاع والإلغاء والضغط، وحماية الملفات والسجلات والملكية. مقارنة محتوى تقارير المبيعات بالمصدر، وفشل/مهلة تلجرام دون تكرار. لا إرسال حقيقي أو NAS حي في اختبار محلي افتراضي.
- للحذف والتلخيص: تطابق الأرصدة والحصص والمال والاستهلاك ومنع الازدواج، ومخلفات الحذف والاستعادة والتزامن. للتحسين: الأقفال والمساحة والتعذر وعدم إظهار إلغاء وهمي. قياس الزمن وCPU/RAM على نفس البيانات وتوثيق الكلفة دون افتراض نسبة تحسن.
- بعد تنفيذ إضافتي FastTrack والأتمتة: إكمال مجموعات الاختبار الخمس السابقة، والتكامل والتغليف والتوقيع والتوقيت وربط الصور وترقية/تراجع مخطط المهام، وبناء واختبار صورة Web النهائية نفسها قبل اعتماد النشر.
